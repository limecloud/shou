Нативна утиліта очищення macOS із правилами, які можна перевіряти та використовувати повторно для проєктів розробки й застосунків.

> **Стан: етап проєктування.** Застосунок і CLI ще недоступні. Нижче описано заплановані можливості. Переклад README не означає, що застосунок уже підтримує цю мову.

## Навіщо потрібен Shou

Каталоги Rust `target`, залежності Node.js, кеші проєктів і результати збирання можуть регулярно заповнювати диск Mac обсягом 500 ГБ. Призначення каталогів залежить від проєкту: назви чи розміру недостатньо, щоб визначити, чи можна видалити дані.

Shou зберігає перевірене рішення щодо очищення як особисте правило: **Знайти → Зрозуміти → Визначити правило → Переглянути → Підтвердити → Використати повторно.** Зміни, які можна описати наявним форматом правил, не потребують оновлення застосунку. Нові можливості рушія й надалі потребують оновлення.

## Заплановані можливості

- **Аналіз за проєктами:** розрізняти результати збирання, встановлені залежності, вихідний код і некласифіковані дані в явно вибраних робочих областях.
- **Особисті правила:** задавати шляхи, ознаки проєкту, умови зберігання та винятки, а потім переглядати об’єкти й ризики.
- **Незалежні застосунок і CLI:** спільне ядро для керування правилами, сканування, планів та історії; кожен інтерфейс працює самостійно.
- **Інтерфейси для наявних агентів:** Codex, Claude Code, WorkBuddy та подібні інструменти можуть додавати вимкнені чернетки правил через стабільну CLI та JSON. Shou не інтегрує моделей, не розробляє й не розміщує агентів.
- **Нативна архітектура:** Swift, SwiftUI та AppKit. Переносне ядро в монорепозиторії; майбутня підтримка Windows потребує окремої реалізації та перевірки.

## Перевірка перед очищенням

Правила не розширюють дозволів операційної системи. Чернетки проходять перевірку й попередній перегляд; увімкнення правила не дозволяє видалення. Кожен запуск потребує підтвердження конкретного плану. CLI не пропонуватиме параметрів для обходу підтвердження.

Типова дія — переміщення до Смітника. Остаточне видалення об’єктів цієї операції потребує окремого підтвердження й не зачіпає решти вмісту Смітника. Обсяг переміщених даних і фактичне вільне місце відображаються окремо. `node_modules` — залежності, що потребують ретельного перегляду, а не звичайний кеш. Назви, файли блокування та вік даних не гарантують можливості їх відтворення.
