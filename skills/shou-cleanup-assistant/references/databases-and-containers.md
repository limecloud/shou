# 数据库与容器

## 数据库

盘点引擎精确版本、实例身份、DATA_DIR、监听方式、库大小、表数与用途证据；只查看元数据，不读取业务正文。正式库白名单须由当前配置与用户选择核实。名字带 test、空目录或已停止都不够。

删除必须使用专用的精确库级操作，绑定实例和已确认名单，保护系统库、当前项目与连接。执行前重新观察，执行后验证目标缺席及非目标库表一致。数据字典登记、物理目录和表空间占用不一致时保留诊断；不手删 mysql.ibd、PG base/global/WAL，不自动升级或补建目录来强制 DROP。旧实例需匹配版本恢复时形成单独维护任务。

## Docker 与虚拟磁盘

识别当前本地 context、后端、容器状态和全部挂载。停止容器可能持有需要保留的卷；dangling 只说明引用情况，不代表业务无用。按镜像、构建缓存、容器、卷分别列具体对象，不运行宽范围 prune 扩大已确认范围。

用管理器先核验内部结果，再核验宿主卷。需要 TRIM 或 VHDX/稀疏镜像回收时说明当前后端支持、活动状态与影响；没有 Shou 适配时仅交接，不把“文件逻辑大小”直接称为可释放空间。
