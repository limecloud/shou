# 清理安全与数据边界

[English](../../security/cleanup-safety.md) | 简体中文

状态：设计草案。本文件定义必须验证的产品约束，不代表已实现安全保证。

## 1. 保护对象与信任边界

主要保护对象：用户的源码、未提交修改、凭据、持久业务数据、交付物，以及在磁盘空间有限时继续工作的能力。

不可信输入包括：导入规则、AI 生成内容、文件名、目录结构、项目 README、本地可被改写的计划文件。规则说明写着“可重建”不构成证据。

下一阶段内置清理专用 Agent 接入用户选择的模型，使用受限调查工具；外部 Codex、Claude Code 等继续通过 CLI 使用同一核心。模型建议不构成启用或删除授权，调查服务不持有删除工具。两条路径均受相同规则、保护、当前确认和执行核验合同约束；内置首版仅发送有界索引元数据，具体实现与限制见[实现记录](../engineering/embedded-ai-implementation.md)。

后续[AI 产品合同](../product/embedded-ai.md)规定默认关闭的桌面总开关和 Jev 优先路由：关闭阻止新的桌面请求，但无法撤回已发送内容，不吊销凭据或关闭 CLI 独立调用；Jev 只处理受控选项，不以低费用或高概率扩大授权。主模型升级限定事先披露的目的地与范围，服务错误不能静默转发。门禁、路由及验收尚待实施，详见[架构与时序](../architecture/embedded-ai.md)。

## 2. 首版威胁模型

| 风险 | 处理策略 | 剩余限制 |
| --- | --- | --- |
| 错误或恶意规则覆盖过广 | Schema、静态语义、根绑定、硬保护、具体预览 | 用户可能误判目录业务用途 |
| 目录链接逃逸 | 不跟随符号链接、junction、reparse point，不跨卷 | 平台特性必须实际验证 |
| 扫描后目标被替换 | 文件身份、完整目录清单、临近操作复核 | 简单路径检查不能消除竞态 |
| 活跃项目被清理 | 项目排除、活动线索、修改年龄与状态复核 | 不能可靠发现全部进程或使用情形 |
| 规则携带代码 | 不执行脚本，不做环境变量或 Shell 展开 | 用户自行在别处运行命令不在产品控制内 |
| 提示注入或终端注入 | 输出转义；项目内容按数据处理，不能改变工具／路径范围；模型参数经本地校验 | 模型仍可能误解用途，外部 Agent 也须遵守自身授权策略 |
| 调查证据发送过多 | 主动启用，说明提供方和发送范围；定向读取、相对路径、字段／内容预算，默认排除完整索引、个人内容与凭据 | 路径和配置片段仍可能包含私人信息 |
| 模型凭据泄漏或上下文转发 | 系统凭据库保存敏感值，日志脱敏；连接测试仅发合成数据，不静默跨服务商重发 | 用户所选服务商的留存策略需要分别说明 |
| 部分成功被误重试 | 执行记录、唯一计划、状态查询、拒绝重复执行 | 崩溃现场可能暂时无法确定 |
| 空间统计误导 | 口径分离、硬链接去重策略和 APFS 局限说明 | 实际释放受系统及其他进程影响 |
| 磁盘满或记录损坏 | 先持久化意图、失败即停止、保留现场 | 不能承诺任何情况下都可原子恢复 |

不把同用户恶意进程隔离作为应用自身可提供的保证。拥有同等文件权限的程序可以绕过 CLI；Shou 的校验不是操作系统权限沙盒。

## 3. 授权范围

- 默认只访问用户选择或显式注册的工作区，扫描不自动扩展到主目录、其他用户或其他卷。
- 注册路径不等于系统授权；GUI、终端、TCC 与未来 Windows ACL 的实际效果分入口检查。
- 缺权限时提供重新授权和缩小范围的路径，不调用 `sudo` 或安装特权 helper。
- 首版可执行清理范围限定本地、受支持的文件系统；网络卷、云占位和未知类型只作明确受限的分析或拒绝访问。
- 规则不能取消用户排除、绕过硬保护、启用跟随链接或扩大根目录。

### 只读子进程边界

桌面端把根身份查询与有预算的遍历交给包内 CLI 的短生命周期子进程。该内部入口只读，不打开记录存储，不能创建计划、确认、移动、恢复或永久移除。它使用当前用户权限，不增加文件访问能力、不绕过 TCC；打包进程的实际访问仍须单独验证。

临时 IPC 目录为 `0700`，文件为 `0600`。读取要求文件属于当前用户、为单链接普通文件、不跟随符号链接，并限制大小。核验请求／结果版本、请求身份、发起的父进程、进度边界和快照路径／覆盖。错误格式、其他请求、不完整或不可用结果均拒绝作为证据，进度不构成授权。

取消／超时仅终止本次自有只读子进程，不等待内核退出；两个存活子进程的上限及父进程／期限 watchdog 限制累积，不能强制正在进行的内核调用立即完成。这是响应性边界，不是同权限恶意进程隔离。已确认变更仍在父进程执行，并保留即时原生复核。自动化已验证取消、超时、存活子进程上限；打包桌面端也已在此前停滞的扫描位置通过停止操作。具体范围见[验收记录](../engineering/acceptance-and-testing.md)，不扩展为任意内核阻塞场景通过。

## 4. 文件保护策略

### 必须阻断

- 工作区根、主目录根、卷根、系统目录和其他用户目录。
- 授权范围外对象，以及作为清理目标或解析祖先的符号链接；无法核验的链接类型同样阻断。
- 已识别的版本控制元数据、凭据与密钥目录、系统钥匙串和 Shou 自身配置及执行记录。
- 已识别的用户项目根、源码根，以及属于这些项目的清单与锁文件作为清理目标。
- 已识别的持久数据库、容器/虚拟机数据盘和用途不明确的共享数据目录。
- 含受保护或排除后代的父目录整体操作。
- 身份、目录清单、权限、规则或排除在确认后变化的目标。

### 必须保持人工判断

Shou 无法普遍识别所有源码、数据库、离线依赖或手工放入构建目录的文件。未识别不代表可删除。

`build`、`target`、`dist`、`node_modules`、`tmp` 等名称只提供线索；候选项需要具体规则、用途说明、边界校验和用户选择。不能用“没有 Git 改动”证明目录内容可以恢复，也不能把 `atime` 作为未使用的可靠依据。

用户项目清单与依赖包内部清单的归属必须分别识别，不能因第三方包含 `package.json` 就把它自动视为用户源码根；也不能仅凭父目录名就豁免整个依赖树。经上下文核验的 `node_modules` 仍属高风险、显式审阅场景；存在版本控制元数据、用户排除、无法核验的链接或用途不明的数据时，保护优先。归属无法确认则不提供执行资格。

目录内部已识别的 POSIX 符号链接（例如 npm `.bin`）作为不透明条目，不遍历指向目标；移动父目录只移动链接本身，永久移除时也只能解除该链接。外部指向对象不进入扫描或执行范围。此行为需要专门测试，不能将未知 Windows reparse point 视作普通 POSIX 链接。

## 5. 扫描与计划完整性

- 只读扫描可以保存结果，但不移动目标。
- 存在权限缺口、预算截断或取消时明确标记覆盖缺口；不完整目标不能执行，独立完整且符合策略的兄弟候选仍可进入计划。
- 每个选中目标须有正向完整覆盖证据及未变化的完整清单；旧 partial 记录缺少覆盖字段不能获得执行资格，清理模式的发现完成不等于全树已测量。
- 计划冻结具体路径、文件身份、完整目录清单、配置与规则版本、动作及有效期。
- 目录父子目标冲突在计划阶段解决；拒绝重复计算和重复操作。
- 用户改变选择、规则或排除后生成新摘要，不使用旧确认。
- 本地计划文件可被改写，执行时需重新验证；持久化的 `approved=true` 不能成为可执行凭据。

## 6. 确认与 Agent 边界

- GUI 以原生界面确认精确范围和后果；空间分析与大文件页通过列表／树图勾选审阅范围，在操作栏展示数量与容量估计，并由删除按钮提示不可恢复后果，点击明确的删除按钮即确认，冻结当前路径和动作后校验执行，不再弹第二次确认。CLI 在交互终端展示范围并主动获取确认。
- 无 TTY 的破坏性 CLI 调用拒绝执行，提供计划与手动确认指引。
- 规则导入默认禁用，Agent 能添加草稿并预览；这不是清理授权。
- 已启用规则与已保存方案都不含长期删除许可，每次清理使用当前具体计划。
- TTY 不能证明调用者是人，外部 Agent 的命令授权由对应产品与用户控制。
- 不以命名“只供 GUI”或“安全执行器”作为安全边界，跨进程确认需要实际合同与权限设计。

## 7. 执行与竞态门槛

1. 取得跨进程执行锁，复核计划与当前用户范围。
2. 对根和目标进行基于文件系统身份的核验，不只做字符串规范化。
3. 对候选后代形成完整清单，临近操作时检查状态变化；任意无法确认部分阻断该项。
4. 平台操作不得跟随新替换的链接；不可复核时拒绝或跳过。
5. 执行意图先持久化，操作后记录真实结果位置和身份。
6. 记录失败时停止启动新项，将无法确认结果标为 `unknown`，后续现场核对。

系统废纸篓调用前先持久化每项的 `moving` 边界，永久移除调用前先持久化 `purging` 边界。调用前日志失败会阻止该次操作，调用后结果写入失败则留下已开始但未完成的记录。永久执行只使用原始路径和不可变完整清单，不能退回按路径递归删除。系统接口报错后，只有原始完整清单仍可复现时才视为已知失败，否则记录不确定结果。历史核验持有同一把修改锁，仅检查记录中的确切位置；无法推断系统调用尚未记录的废纸篓目标，不授予重试权限，也不枚举其他废纸篓内容。未完成的后续意图保持阻止，即使之后观察到原位置似乎已恢复。

文件系统检查与操作之间的时间竞争不能靠文档消除。macOS 的 `FileManager.trashItem`、目录句柄与防替换策略必须在 M0 进行实际原型与故障注入；如不能满足约束，就缩小支持场景或推迟执行能力。永久移除需逐项约束到计划清单，不能对可变目录退回无界递归删除。

生成源码例外需要与包内完全一致的受信规则和原生归属／活动事实，个人规则不能申请这些例外。已识别的 Rust `OUT_DIR` 与 Swift 生成产品，不豁免相邻源码检出、清单、凭据或仓库保护。Cargo 解包源码还须具备未变化的源码清单、核验后的校验和与匹配的本地保留归档。工具缺失、构建进程活动、受版本控制内容、修改或证据不可用时均拒绝执行。

执行停止在安全项目边界协作完成，不承诺中断正在进行的单次系统废纸篓调用。须核对该调用、保留已完成事实并准确标记剩余项目；停止请求不是回滚。

只读检查与执行前复核仍可取消。废纸篓移动或恢复意图已持久化后，原生路径及目录清单检查完成当前项，不继承只读 worker 的取消；身份、不跟随链接、归属、预算及禁止覆盖检查仍执行。取消后不启动下一项，未开始的恢复不产生后续操作意图。永久移除可在后代条目间停止，中断项目记为失败／部分完成，不计成功移除。已核验清单内的单项权限或普通 I/O 删除错误不阻断其他条目和后续所选目标；未删完的目录保留，记录部分结果及有界失败路径。身份变化、链接替换和未知结果仍停止，日志失败仍禁止启动新操作。桌面退出／关窗等待执行完成，遇到错误或未知结果保留窗口；不会因此产生恢复授权或重试未完成意图。

## 8. 废纸篓、永久移除与恢复

### 移到废纸篓

用户主动选择的可恢复方式，记录系统实际返回的位置与身份；不自行猜测废纸篓文件名。失败时不退回直接删除。

同卷移入废纸篓通常不释放占用；结果显示“已移到废纸篓”，不能显示相同数值的“已释放空间”。

### 永久移除本次项目

清理计划的 `action=permanent` 是桌面清理默认的一等执行动作，一次范围确认且不可恢复。每个绑定项目都要重新核验当前配置、活动状态、对象身份和完整清单；缺失、替换、扩展或无法核验的对象跳过或失败，并记录 `operation=permanent_cleanup`、`purging` 和 `purged`。不清空其他废纸篓内容，也不由规则直接触发。

结果分别显示永久移除项目估计容量与卷可用容量前后观测。APFS 克隆、硬链接、快照、打开文件和系统行为会影响实际释放；估算值不承诺新增可用字节。

### 恢复

恢复前核验对象与目的位置，不覆盖已存在文件；冲突时用户选择其他位置或取消。永久移除、系统清空废纸篓、权限变化或对象缺失可能导致无法恢复。批量清理不是可事务回滚的操作。

仅对已记录的废纸篓目录，后续核验可以忽略 macOS 异步元数据更新导致的顶层 `ctime` 变化；根对象身份与其他根字段必须匹配，完整后代清单必须一致。内容变化、新增后代、对象替换与其他元数据变化仍阻止恢复或永久移除。普通扫描和移入前复核保持原有比较。

## 9. 日志、隐私与存储

- 本地运行无需账户；首版无默认遥测和自动上传。
- 日志记录对象 ID、阶段、错误与必要路径，不读取或记录源码正文、密钥和业务内容。
- 机器输出与导出摘要可能含私人路径，分享前提供相对路径与脱敏选择。
- 不向 CLI 或分享规则输出 bookmark、凭据、访问令牌。
- 配置与记录目录按平台使用当前用户访问限制；临时文件同样受限。
- 保存方式须经断电/崩溃、磁盘满和文件锁测试；不能仅以写入返回成功推定持久安全。

## 10. Windows 特有验收

Windows 文件清理界面已按同一 Core 当前确认与执行合同组装源码，GUI 和 CLI 共用关闭的原生验收门禁。正常关窗只请求停止并等待当前任务，强制终止不承诺完成日志；停止后的真实结果必须展示。查询不到结果不证明目标未变更，不能恢复执行资格或自动重放计划。界面状态测试与 C# 引用编译不代表原生确认、删除或关窗行为通过验收。

Windows 系统卸载与 Shou 文件清理分别授权。注册表卸载字符串不作为可执行命令；准备计划必须重新核验 MSI／MSIX 精确身份与已审阅摘要，并单独允许系统安装程序管理的数据影响。该同意不包含额外残留，也不构成当前执行确认；普通 MSIX 移除不能承诺保留应用数据，系统还可能移除不再使用的依赖包。审阅和限时计划包含安装目录内的有界活动观察，活动或未知结果阻止计划；外部组件不在该观察覆盖内，不能把当前空闲观察当作可复用执行授权。执行源码在当前进程确认后获取变更租约、重新核验并先保存意图；系统适配再次核对用户、事实及授权期限。确认最多一分钟且只能消费一次，任何已有意图阻止同一计划重放。安装程序结果与安装身份观察分开记录，日志失败及未知结果不证明没有变更。系统安装程序可能停止其管理的应用／服务并改变数据；Shou 不杀死 MSI 进程，MSIX 仅请求合作取消并等待终态。WinUI 确认对话框默认取消；停止后继续等待真实结果，执行期间阻止离开应用页，正常关闭窗口会请求停止并保持窗口打开。强制终止仍可能只留下未完成意图，不能推断卸载终态。GUI 与 CLI 共用关闭的执行门禁，原生验收和恢复待完成。详见[应用卸载边界](../product/application-uninstall.md#安装身份审阅与计划)。

Windows 后续实现需单独验证：junction/reparse point、卷挂载点、长路径、Unicode 与大小写、ACL、被占用文件、回收站对象身份、恢复冲突、锁与原子提交、运行库及干净环境安装。

平台不支持回收站时返回能力不可用，禁止替换为永久删除。macOS 上的模拟测试、交叉编译或共享规则测试不能替代 Windows 实机证据。

## 启动项发现

Windows 使用独立只读启动项链路，覆盖十个注册表／文件夹／计划任务／包清单来源。不打开清理记录，不执行注册命令、不解析快捷方式，也不授予控制权限。注册表原始数据有界读取并回读核对；只把无歧义的可执行线索交给 Core，丢弃参数和环境变量值。目录元数据使用拒绝 reparse 的原生适配；计划任务仅通过当前身份的本机只读 COM 读取，含开机／登录触发器才发布，参数和 XML 不离开 Platform。包清单使用拒绝 reparse、有界、元数据复核的只读句柄；普通清单硬链接不授予任何变更权限，规则读取仍拒绝多链接。打包声明发布前回查包注册，不把清单 Enabled 当作有效状态。预算消耗未知时停止后续来源。启用、进程及残留状态保持未知，明确列出范围外来源与不完整覆盖；原生夹具和 UI 检查仍待完成。详见 [Windows 启动项合同](../product/startup-items.md#windows-启动项合同)。

计划任务引擎状态是公开任务属性的独立只读观察。双读状态与路径／XML 复核限制发布，但不构成原子快照；状态失败／变化保留注册并报告缺口，Core 拒绝非法枚举或来源。该链路不执行、启停或注册任务，不根据任务引擎状态判断启动触发条件或应用进程。

首阶段只读取固定 launchd 配置目录，不修改注册、不结束进程、不启用服务或删除文件。拒绝祖先／末级链接和特殊文件；文件／来源身份变化、权限拒绝、无效配置及条目／时间限制均在覆盖范围中显示。单文件最多 256 KiB，默认预算为 2,000 条目和五秒，在操作之间检查取消；内核阻塞调用可能超出协作取消时限。

仅保留 Program 或 ProgramArguments 首项中可显示的绝对可执行路径，其余参数与环境变量值不保留、不输出。当前用户 LaunchAgent 可以包含有界、瞬时的 `launchctl` 状态观察；查询不可用时保持 unknown，任何状态都不授予修改权限。Disabled 仅作配置线索。登录项、后台注册和应用内辅助程序需在原生系统设置中查看。发现不依赖清理存储，也不申请新权限。见[启动项发现](../product/startup-items.md)。


## 应用卸载

卸载使用确切应用身份和完整标识关联，不通过缓存规则例外扩大删除范围。个人数据需单独同意并明确选择组件。发现重复标识时保护关联数据；发现范围不完整时提示并取消关联组件自动选择。共享组容器只有系统元数据确认当前标识时才会进入；无法确认的容器、外部注册和原应用已不存在时的独立残留发现仍不在此阶段范围内。系统／当前应用、当前账户运行中的可执行程序及辅助程序、未知活动、其他所有者内容、特殊文件、多重硬链接文件、保护存储和排除项会阻止处理。

普通工作区对 `/Applications` 的限制不放宽。每项回执校验其组件类型对应的确切原位置；应用父目录使用独立、固定安装范围的身份能力。独立文件需要不超过16 MiB的有界内容证据。文件与目录共用持久化意图、原生废纸篓返回结果核验和不覆盖恢复。卸载回执仅允许恢复，不增加永久移除流程。覆盖、进程限制及取消语义见[应用卸载](../product/application-uninstall.md)。


## 空间分析直接删除

空间分析支持本地卷或目录发现，以及明确选中文件和目录后的直接删除，独立于清理规则工作区。桌面列表和树图共用导航与去重选择；确认及执行时核验当前完整清单和排除配置，复用既有执行日志与历史。详见[空间分析架构、流程与时序](../product/space-analysis.md)。

Windows 计划任务开关不由启动发现、任务状态或持久化审阅授予权限。只对当前用户所有、当前用户字面主体且明确声明交互式普通权限的开机／登录任务建立内存审阅；当前入口确认、租约下重查与持久化意图先于 Enabled 设置。派发后等待真实结果，未知结果不重放、不自动回滚；公共门禁保持关闭。资格和竞态限制见[启动项合同](../product/startup-items.md#计划任务开关审阅与控制)。

Windows 多位置计划的安全合同由[日常清理](../product/unified-cleanup.md#windows-扫描与审阅)定义。每项绑定确切扫描来源，单个计划摘要覆盖全部根、规则和清单；当前确认只授予这个计划一次执行。所有来源预检通过前不写执行意图或修改任何目标；一旦有意图，整个计划不可重放。选择筛选和推荐不扩大权限，未知结果停止后续位置。
