# 国际化与本地化

[English](../../product/internationalization.md) | 简体中文

状态：设计草案。文档翻译与应用语言支持分别维护，不能相互替代完成证据。

## 1. 目标

面向全球开发者提供一致的产品说明、规则解释和清理确认。公开文档以英文为默认入口；桌面应用首次启动使用简体中文，之后记住用户明确选择的语言；机器合同保持语言无关。

## 3. 文档结构与维护

- `README.md` 为英文首页；`README.<locale>.md` 提供本地化概览。
- `docs/` 保存英文技术文档；`docs/zh-CN/` 保存同路径简体中文版本。
- 所有翻译提供英文入口，采用本机相对链接，避免依赖个人目录。
- 公开示例使用虚构项目与容量范围，避免对话指代、个人路径或未经归因的测量结果。
- 合同字段、需求 ID、命令、状态、错误码和安全约束必须在两套技术文档中一致。
- 新语言以独立文件和审阅记录加入，不复制多套机器 Schema。
- 文档更新同步维护语言版本；译文滞后时明确标记，安全说明和破坏性操作文案不得带已知歧义发布。

## 4. 桌面端

- macOS 使用 String Catalog（`.xcstrings`），开发语言为英文；首次启动或已保存语言不受支持时默认简体中文（`zh-CN`），保留已有的有效选择（`zh-CN` 或 `en`）。
- 主窗口工具栏和设置共用同一个语言偏好；切换后导航、摘要、状态提示、原生表格表头与行内容、日期格式立即更新，无需重启或重新扫描。保留扫描结果、展开行和清理勾选，重启后保持语言选择。
- 按实际资源标签查找翻译，忽略标签大小写：SwiftPM 输出 `zh-hans.lproj`，String Catalog 使用 `zh-Hans`。在同一进程验证双向切换，并检查应用包中的资源。
- 使用完整句子、占位符和复数规则，不拼接用户可见句子。
- 日期、时间、数字与容量使用本地化格式化器；容量口径保持十进制，并在需要时显示精确字节。
- 文件路径、规则 ID、对象 ID 和命令保持原值，不翻译文件名。
- 表格、工具栏、sheet 和辅助功能标签允许文本扩展，使用伪本地化和长文本验证。
- 繁简中文独立审阅，不以字符转换替代术语和交互校对。
- 为未来从右到左布局保留方向能力，当前不据此声明已支持相关语言。
- Windows 使用其原生资源体系实现同一语义，不把 `.xcstrings` 作为 Windows 运行时资源。

## 5. CLI 与机器输出

- 人类文本的语言优先级：`--locale` → 已保存的应用语言偏好 → 系统有效 locale → 英文。
- 接受常见系统 locale 别名，如 `en_US.UTF-8`、`zh_CN.UTF-8`、`zh-Hans`，映射到受支持语言；未知显式值返回输入错误，系统未知值回退英文。
- `--locale` 只影响提示和解释，不改变命令名、参数、ID、状态或策略。
- JSON 字段、错误码、枚举与机器命令使用稳定英文标识；字节为整数，时间为 UTC ISO 8601。
- JSON 中可读消息可以本地化，但调用者不得解析消息文本判断成功与否。
- 交互确认使用当前显示语言，绑定相同计划摘要，不通过解析本地化消息执行文件操作。

## 6. 规则文案

规则匹配、路径和风险枚举与显示语言无关。共享规则示例采用英文基础文案；个人规则允许任意 Unicode 文本。

首版不增加模型翻译，也不为不同语言复制同一规则的执行定义。多语言模板的显示资源按稳定规则 ID 与版本关联；缺少译文时显示原文。完整性摘要绑定原始规则内容，不因 UI 翻译切换而改变执行范围或重新解释条件。

## 7. 术语

| English | 简体中文 | 说明 |

| Workspace | 工作区 | 用户授权或注册的根范围 |
| Rule | 规则 | 声明式匹配与条件 |

| Installed dependencies | 已安装依赖 | 不统称缓存 |
| Move to Trash | 移到废纸篓 | 不等于立即释放空间 |
| Permanently remove | 永久移除 | 不可恢复的独立动作 |
| Execution receipt | 执行记录 | 逐项操作事实与状态 |

## 8. 验收

每个发布语言覆盖导航、错误、风险、确认、恢复、无权限、部分扫描和辅助功能标签。使用长文本、复数、非拉丁路径、时区和系统 locale 别名测试。

英文与简体中文的同一计划必须具有相同 ID、摘要、候选集合和安全决策。新语言在文案审阅与交互测试后才列为应用支持语言；文档多语言不计入运行时语言验收。
