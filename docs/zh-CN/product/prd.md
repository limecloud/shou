# Shou 产品需求文档

[English](../../product/prd.md) | 简体中文

状态：设计草案。版本：0.1。日期：2026-10-19。

## 1. 产品定义

**Shou · 收拾一下** 是一款使用 Swift 开发的原生 macOS 清理工具，帮助用户发现空间占用，把个人经验或 AI 建议转成声明式规则，再通过可解释的预览完成清理。

品牌表达：**Tidy up. That's it. / 收好，就好。**

首个目标群体是使用有限容量 Mac、同时维护多个项目的开发者。产品价值在于适应每个人的项目和工具链，并减少反复人工查找、判断、清理的劳动。

平台路线：macOS 先交付，未来支持 Windows。工程从开始采用 monorepo，保留可移植 Swift 核心与平台适配边界；首版完成不代表 Windows 已可用。

## 2. 背景

### 2.1 开发工作区的空间管理问题

约 500 GB 容量的 Mac 在多项目开发场景中，容易因缓存、编译产物与临时目录持续累积而出现空间不足，需要频繁清理。

Rust `target` 可累积至数十 GB，`node_modules`、前端与 Electron 构建输出也可能占用数 GB。产品需要区分项目依赖、构建产物与重要源码，并将经审阅的清理策略复用于不同项目。场景与统计口径见[开发者空间场景](developer-space-scenarios.md)。

这类空间问题具有明显的个体差异：

- 语言、框架、构建方式与项目目录各不相同。
- 自研软件产生的缓存，通常没有公共规则可用。
- 同样名为 `build`、`dist`、`cache` 的目录，可能分别是可重建产物、待发布文件或重要业务数据。
- 删除后能否恢复工作，取决于源文件、工具链、网络、依赖仓库和用户自己的生成流程。
- 全盘扫描结果很多，但用户仍要自己判断哪些是项目里真正可以处理的空间。

现有固定规则和手工命令难以持续覆盖这些差异。用户已经知道某些目录可以清理，却仍要反复进入目录、执行命令、核对结果。

### 2.2 AI 工作流中的缺口

用户可以请 AI 分析目录或写清理命令，但缺少稳定的产品接口承接结果：

- 建议常以自然语言或一次性 Shell 命令出现，难以审阅、复用和追踪。
- 应用缺少公开规则格式、只读预览和机器可读的结果。
- AI 的建议与本机实际文件状态、权限、排除设置之间没有可靠校验。
- 模型能够写出删除命令，并不代表它了解哪些文件对当前用户不可替代。

Shou 提供一个本地、可审阅的规则与计划层，承接用户和现有 AI Agent 的清理意图。这里的 Agent 指 Codex、Claude Code、WorkBuddy 等外部产品，Shou 不接入任何模型、不开发 Agent。

## 3. 目的与收益

| 目的 | 用户收益 | 产品侧可验证结果 |
| --- | --- | --- |
| 减少重复寻找目录 | 不必每天逐个项目查占用 | 已保存方案可重新扫描并生成预览 |
| 覆盖个人目录 | 自研软件也能建立清理规则 | 用户可独立新增规则，不修改应用代码 |
| 降低判断负担 | 看清用途、命中原因和清理代价 | 每个候选项具有解释、风险与证据 |
| 适配 AI 协作 | 将 AI 建议变成可验证的规则 | 外部工具能校验规则并取得 JSON 结果 |
| 提高清理可控性 | 清楚知道将处理什么 | 执行只针对用户确认且仍然有效的计划 |
| 保持 Mac 体验一致 | 学习成本低，常用操作顺手 | 原生导航、表格、菜单和辅助功能可用 |
| 兼顾两种使用场景 | 桌面查看直观，终端操作连贯 | 两个入口都能独立完成完整核心任务 |

空间收益受具体目录与磁盘状态影响，不承诺固定释放量或性能提升比例。

## 4. 用户与任务

### 4.1 主要用户

- **多项目开发者**：维护多个前后端、移动端、Rust 等项目；希望清理闲置产物，保留正在工作的项目。
- **自研工具作者**：知道自己的工具产生哪些临时目录，希望将经验固化为规则。
- **AI 辅助开发者**：希望让自己的 AI 工具帮助分析，再由应用完成确定性的验证与执行。

### 4.2 后续用户

一般 Mac 用户可使用经过验证的通用规则和空间分析；团队可分享不含私人路径的规则模板。首版不以企业设备管理为目标。

### 4.3 核心任务

> 当磁盘又快满了，我希望快速找出各项目中可以处理的大目录，将适合自己的判断保存下来，下次确认后就能清理，而不是重新查找和写删除命令。

## 5. 产品原则

1. 清理意图与文件操作分开，先解释再执行。
2. 规则可以变化，执行安全约束始终由引擎控制。
3. 不因为目录很大或名字像缓存，就断言其可删除。
4. 内置规则、手写规则和 AI 草稿经过同一校验流程。
5. 新用户通过界面完成核心任务，不必先写 JSON 或配置模型。
6. 后台扫描可取消，首版不提供无人值守删除。
7. CLI 是独立产品入口，不是只能拉起 GUI 的附属工具。
8. 桌面遵循各平台原生习惯，共享业务合同；macOS 使用 SwiftUI，Windows UI 技术在平台原型阶段确定。

### 6.1 首版明确不包含

- 强制登录、云端扫描、默认遥测。
- 执行规则提供的 Shell、JavaScript、Swift 或其他脚本。
- root 清理、SIP 绕过、系统“加速”、内存清理。
- 无人值守删除、定时永久删除、自动清空整个废纸篓。
- Docker、虚拟机、数据库等产品内部的物理数据目录直接删除。
- 根据目录名自动勾选整个 `node_modules`、`dist`、`Downloads` 或工作区。

相关生态后续优先通过官方接口与专门适配器支持，而非通用路径猜测。

**长期产品边界**：不接入任何模型，不开发 Agent、聊天助手或模型编排平台。Agent 友好意味着现有 Agent 能发现命令、读取结果、生成和添加规则；模型费用、对话上下文与 Agent 运行由用户所用的外部产品管理。

## 7. 关键需求

### 7.1 工作区与扫描

- 用户选择工作区，首版不默认扫描整个主目录。
- 大目录没有清理规则也应出现在空间分析中，标为“待判断”，支持据此起草个人规则。
- 授权失败、路径消失、扫描取消与部分扫描都要保留明确状态，不能显示“全部完成”。
- 同一目录被多个规则命中时仅计算和执行一次，保留全部命中解释。
- 父子路径不能在一个计划内作为两个独立删除目标重复计算。

### 7.2 自定义规则

- 简单向导覆盖“选择目录 → 判断依据 → 保留条件 → 预览 → 保存”。
- 高级用户可编辑版本化 JSON，通过 CLI 验证。
- 规则与工作区绑定分离，分享模板时不携带用户名与绝对路径。
- 新规则、规则更新与 AI 草稿均不自动执行；更新后必须重新预览。
- 新的路径和条件在现有规则格式内可立即使用；新增引擎原语仍需应用升级。

### 7.3 预览、清理与恢复

- 无默认全选；首版由用户明确选择本次清理范围。
- 详情包含原路径、实际占用估计、命中规则、重新生成条件及风险。
- “一键清理”指复用已审阅方案后，从最新预览中确认执行，不等于跳过确认。
- 默认移到废纸篓，成功后提供逐项记录与尽力恢复。
- 永久移除与移到废纸篓必须在按钮、确认和结果中区分。
- 永久移除仅针对本次有有效记录、仍可核验的清理项，无法恢复，不操作其他废纸篓内容。

### 7.4 AI 友好

- Codex、Claude Code 等现有 Agent 可以协助解释、起草和添加规则；Shou 自身不调用模型。
- 规则格式、错误码与扫描结果有版本，便于用户自己的工具接入。
- 首版 CLI 独立完成扫描、计划与执行，终端执行也须展示具体范围并明确确认。
- 非交互调用支持只读分析、规则草稿导入与预览；首版没有跳过确认的 `--yes` 或 `--force` 删除入口。
- 仓库名、文件名、README 和扫描到的文本均是数据，不是可信指令。
- 用户主动导出后自行发给 AI；首版应用不主动上传本地信息。

## 8. 体验要求

- 采用系统窗口、侧边栏、工具栏、表格、检查器和系统文件面板。
- 支持浅色、深色模式、键盘操作、VoiceOver 和系统字号。
- 清理动作应说明对象与方式，例如“移到废纸篓 · 6 项”，避免模糊的“优化”。
- 空间分析区分逻辑大小、分配大小估计、移到废纸篓容量和卷可用容量变化。
- 即使磁盘已满，也能给出最小错误反馈；记录无法持久化时不得开始破坏性操作。

详细页面与交互见 [macOS 产品体验](macos-experience.md)。

多语言文档、桌面资源、CLI locale、术语和翻译验收见[国际化规范](internationalization.md)。其他语言在翻译包与交互验证完成后启用，不因 README 存在而声明应用已支持。

## 9. 指标与验证方式

以下为初始验证指标，不是效果承诺。首版使用本地测试与经同意的访谈，不默认收集用户行为。

| 指标 | 定义 | 验证方式 |
| --- | --- | --- |
| 首次任务成功率 | 从授权工作区到完成一次明确确认的清理 | 小规模可用性测试记录成功与失败原因 |
| 重复劳动减少 | 同一工作区第二次清理所需人工步骤与时间 | 对照首次手工流程和保存方案后的流程 |
| 个性化覆盖 | 用户真正想处理的目录中，规则能够描述的比例 | 收集匿名化目录类型与未覆盖条件 |
| 规则可解释性 | 用户能否说明为何命中、后果是什么 | 在执行前提问验证理解 |
| 误处理防护 | 安全用例中的越界、符号链接、变化对象被阻止 | 自动测试与故障注入；阻断缺陷为零才发布 |
| 扫描与界面响应 | 指定数据集与设备上的耗时、内存和交互延迟 | 固定夹具、设备与存储条件的基准测试 |

性能预算与发布门槛见[验收与测试](../engineering/acceptance-and-testing.md)。

## 10. 风险与待验证假设

| 风险或假设 | 处理方式 |
| --- | --- |
| 用户不愿写规则 | 原生向导、少量可靠模板、从具体目录起草 |
| AI 建议不正确 | 显式草稿、确定性校验、人工确认与运行时复核 |
| 废纸篓未即时释放空间 | 独立永久移除流程，容量口径分开 |
| 正在构建导致文件变化 | 检测到活动或状态变化即阻止或跳过，要求重新预览 |
| macOS 权限在 GUI 与 CLI 间不同 | 分入口验证，缺权限就报错，不假设权限继承 |
| 原生文件操作无法满足预期竞态边界 | M0 专项原型验证，不满足则缩小首版范围 |
| 规则覆盖广但维护成本高 | 首版限制场景，记录每条模板的证据与回归用例 |

## 11. 产品定位

Shou 的产品选择是将 **个人规则 + 开放机器接口 + 可审阅清理计划** 作为第一阶段主线，先解决一个人的真实工作区，再扩展通用清理场景。

## 首次使用的交付要求

选择工作区后，首轮扫描必须通过内置规则识别常见构建产物和缓存；个人规则用于扩展覆盖。提供分类清理与空间分析两个入口，目录列表与面积图支持逐层查看，未知大目录可直接创建个人规则草稿。所有候选初始不勾选，Node.js 已安装依赖保持高风险，受保护内容不能通过内置规则绕过。

桌面默认入口一键以清理模式扫描明确的应用／开发工具缓存位置及已登记项目，不隐式遍历主目录发现项目。当前目录包含 74 条模板与 35 个固定位置，覆盖项目产物、npm、Cargo、开发工具、Xcode、浏览器及具体应用缓存。应用支持目录整体、聊天记录、活跃 Agent 会话及虚拟机数据不视为可清理缓存。

桌面与 CLI 共享位置发现、规则匹配、有界扫描、应用活动检查、计划与执行记录。缺失位置跳过，权限失败及不完整扫描明确展示。按位置审阅，初始无勾选项，确认页显示确切路径；完成后分别显示移入、跳过、失败与需核验的结果。移入废纸篓不等于已释放空间；恢复只使用已记录、可核验的对象，不覆盖已有目标。

清理发现沿规则前缀遍历，命中目标后完整测量；该模式的 `complete` 不是全树占用结果，空间分析需要 `full`。partial 扫描只允许独立完整且符合策略的目标进入计划，旧记录缺少覆盖证据不能获得资格。执行提供真实进度和安全项目边界上的停止请求，不承诺中断正在进行的单次系统废纸篓调用。

更广泛应用缓存覆盖、辅助功能、性能基准和发布验收仍须分别交付，不能用隔离检查替代。
