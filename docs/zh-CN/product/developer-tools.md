# 开发者工具管理

[English](../../product/developer-tools.md) | 简体中文

“工具”下的“开发者工具”和 [AI 工作台](ai-workbench.md)是两个独立页面。前者组织语言运行时、服务和开发实用工具，后者组织 AI 软件；开发项目产物清理仍属于“应用与项目”。软件安装、卸载和清理候选不能互相授予权限。

## 当前实现与完整目标

目标覆盖参考截图中的全部 17 类模块。共享目录 [developer-tools.json](../../../packages/shou-core/Sources/Resources/developer-tools.json)目前有 79 项，其中 18 项属于 AI；目录收录不代表服务、站点或安装适配全部完成。54 项有已观察到的 Homebrew 包引用，28 项有 WinGet 包引用，实际可操作性还受当前来源、平台、版本、安装身份和验收门禁约束。弃用来源可以用于识别已有安装，不能据此继续安装。

[全量能力与领域边界](../engineering/developer-tool-capability-map.md)列出参考的 71 个根模块、38 个内部工具及嵌套管理器，区分安装、实例、项目、站点证书、容器、网络、任务与 AI。已有软件的专属目录是实现子集，不能将其作为完整功能范围。

| 能力 | macOS 工作区实现 | Windows 工作区实现 |
| --- | --- | --- |

| 安装／卸载审阅、限时授权和日志 | Swift Core；Homebrew 固定参数适配 | C# Core；官方 WinGet COM 适配源码 |

## 发现与已有环境

进入工具模块先只读识别已有环境。已安装视图来自当前观察，不由收藏、显示开关或目录名称推断。包管理器登记、npm 元数据及普通可执行文件分别标注来源；没有运行发现的程序来探测版本，也不把存在文件写成“可正常运行”。有元数据版本时显示版本；仅找到文件时显示“已检测到程序／版本未核实”。

我的工作台呈现用户选入的分类工具列表，右侧来源表保留版本、实际目标路径及各启动入口。macOS 额外识别固定身份的 Claude Desktop／Ollama 应用包；Windows npm 包装脚本通过匹配包名的有界元数据读取登记版本。未安装可选管理器本身不构成读取失败。

多版本和不同来源分别保留；已解析到同一管理器版本目录的 PATH 别名不重复计为另一份安装。识别有目录和结果预算，管理器不可读或超出预算时报告部分覆盖。未发现只表示本次扫描的来源没有匹配，不能断言整台电脑未安装。自定义数据根、所有其他版本管理器、WSL、容器内部和完整磁盘发现未覆盖。

发现不会迁移、重装、修改 Shell 配置、PATH、数据库、配置或正在运行的服务。当前用户支持的软件实例另行盘点；只有已核实完整恢复配方并收到当前操作请求后才进入生命周期控制。变更前始终重新检查当前选定的安装来源。已有 npm 安装不能用 Homebrew 卸载；在其他来源新增副本必须在来源审阅中明确呈现。

## 安装和卸载合同

安装与版本页面按确切来源和安装路径展示已安装版本、可用版本及一个“卸载”入口，不再把已安装包重复放入可用软件包列表。服务概览按实例展示状态；服务行的卸载入口指向它实际使用的安装。多个服务共享同一安装时，卸载详情列出全部受影响实例，逐项停止并核实后才启用确认；不因存在多个服务就禁用卸载入口，也不把卸载共享程序描述为只删除某个服务。卸载范围覆盖该来源核实的版本集合，不包含独立数据目录清理。Windows 同步布局与审阅源码，安装器和服务变更门禁保持现状。

Core 从共享目录接受确切包身份，持有两分钟内有效的一次性当前计划。计划绑定动作、管理器／源身份、安装状态、目标版本及平台证据；确认前与派发前均复查。读取来源不授予变更，变更前取得平台私有记录租约并持久化意图，执行后另行保存核验结果。过期、来源变化、版本变化、确认不匹配或意图落盘失败均不能派发。

Mac 仅调用既有可信位置的 Homebrew，使用固定参数数组，不调用 Shell、sudo、自动安装管理器、自动接受许可、`zap`、`force`、`autoremove` 或依赖清理。安装会由 Homebrew 解析依赖并可能运行软件配置步骤；审阅展示声明的直接依赖，并说明传递依赖与包管理器影响，不将其描述成已冻结每个传递依赖版本。卸载永久移除包管理器管理的软件本体，Shou 不主动删除数据库、模型、项目、账户或配置；包自身的卸载钩子仍可能修改它管理的文件，不能承诺所有安装器都不改变数据。

Windows 核对系统预定义官方 WinGet 源、精确 ID、当前版本、安装身份和当前用户／全机范围。安装固定目标版本，不允许忽略哈希、强制、自动接受协议、未知版本升级或自动重启，依赖派发关闭。安装器进入派发后等待实际终态，停止不能当作回滚。现有清理、应用卸载和启动项门禁不因此打开；本模块安装器门禁也须独立验收。

退出／关闭等待当前安装器结果。进程失败、超时、核验缺失或安装状态不符报告“结果需要核实”，不自动重试、不展示虚构释放容量。安装成功必须读回目标版本；卸载成功必须读回对应来源不再登记该包。这个核验不等于新安装程序已经能够正常完成其全部功能。

## 页面与工程归属

开发者工具与 AI 工作台均以“我的工作台”为首个默认入口，只显示用户选入的工具。第二个入口“添加工具”按类别列出软件，胶囊开关仅表示加入／移出工作台；已安装状态和来源融合在工具条目中，可用“仅看已安装”过滤，不再增加独立的已安装 tab。选择立即保存，返回工作台后直接管理。移出工作台不卸载软件、不停止服务；运行状态与展示选择分别使用明确的可访问名称。

工作台使用左侧独立滚动的分类工具列表与右侧详情；批量读取已选工具的服务状态，左侧每行统一展示名称、状态与进入箭头，只负责导航；启停统一放在右侧确切实例行，多实例分别显示。不需要逐个点开工具才能更新左侧状态。没有选入工具时显示明确的添加入口，不自动把全机已安装软件加入工作台。详情保留来源、版本、路径及安装／卸载的一次审阅；Mac 已接入的 Homebrew 配方共用版本表，不再仅为 MySQL 显示可用与已安装版本。安装使用强调色，卸载使用红色；动作按钮使用“卸载”，点击后在现有详情中审阅确切来源与影响。

Swift `DeveloperTools`／C# `DeveloperTools`拥有目录校验与安装领域服务；Platform 拥有发现、受控管理器调用、系统身份与记录；原生 UI 不生成命令或根据文件名扩大卸载权限。目录是唯一来源，Windows 由共享资源生成器复制并绑定摘要。来源、图标及功能变化同步更新 [SYNC.md](../../../SYNC.md)。

参考分析见 [工具管理参考与实施差异](../engineering/tool-management-review.md)。测试必须区分纯领域、生成管理器夹具、真实包管理器只读发现、WinUI 界面与原生安装器；不能互相代替。真实个人软件只读检查与审阅取消，不作为安装／卸载回归样本。


首屏不等待全机扫描；先显示页面与会话结果，本地元数据和管理器来源在后台逐步合并，服务按已选工作台集合批量核验。只读扫描期间可搜索、切换工具和离开页面，变更动作等待本轮核验。各工具保留独立检查时间，重复进入不重复盘点；手动刷新更新结果，旧观察不授予操作权限。

## 服务胶囊开关

左侧工具列表不放服务开关，所有工具使用相同的导航行。右侧已核实实例使用胶囊开关直接启停；有多个服务时按来源分别展示，不猜默认版本。未知状态不显示虚假的关闭状态；未接入的安装显示原因。AI 软件使用完全相同的开关及来源列表，普通 CLI、MCP 声明和技能存在不代表后台服务，不能用收藏代替启停。

点击即请求当前显示来源／版本的一次启停，不增加层层详情和确认弹窗。Core 消费精确观察，在私有变更租约下重新检查、先写意图再派发，等待系统状态后独立写结果。失败或不确定不自动重试，刷新前不再开放旧观察。执行期间禁用来源切换并等待当前操作收尾。

Mac 支持目录中已安装且仅有一个版本的当前用户 Homebrew 服务。包管理器、配方、安装目录、服务定义及进程身份分别核验；用户登录 plist 必须与包内定义相同。KeepAlive 服务不使用可能返回 0 但未停止的 Homebrew `kill`；对已核实加载域与定义位置的任务执行 launchd bootout／bootstrap，已加载但未运行时使用 kickstart，保留持久 plist 和 disabled override。未知域、多个 keg、自定义或其他用户定义保留不可控制。生成管理器与真实临时 launchd 专项分别取证。

本机实例与安装来源分离。Swift Platform 使用四种关闭的配方策略：Nginx master/prefix/config、MySQL defaults-file/data/socket 参数、Redis 配置与 pidfile/工作目录关联、PostgreSQL 明确 DATA_DIR。相同程序的多份实例分别显示 PID 和配置；完整恢复方案先于停止持久化，停止后核实绑定 worker 退出，再启动。配方缺失或监督方式未接入时保留运行事实与具体原因，不先停后猜。覆盖限定为支持的当前用户进程，不能宣称全机所有用户／所有软件均可控制。详见[逐软件适配设计](../engineering/developer-tool-adapters.md)。

Windows SCM 适配只考虑明确 WinGet 安装路径中的普通单链接可执行文件，并重新核实包、版本、安装位置、SCM 配置及访问能力。启停不改启动类型、不提权、不强杀进程。公开执行门禁保持关闭，胶囊仅呈现已知只读状态；原生生成服务专项验收尚未完成。

### 状态、重启与来源边界

列表明确显示实例的运行中、已停止、操作中和状态未知。检查时间与“刷新状态”说明观察时效；完整刷新同时清理旧包审阅并重新盘点 AI 配置。重启在同一变更租约内先停止、核实同一来源／版本已停止并保存阶段回执，再启动；停止失败不派发启动，启动未完成则保留已停止的部分结果，不回滚或自动重试。

Homebrew 软件本体可能被其他工具以自己的配置启动，因此 Homebrew 服务已停止不等于该程序没有运行。本机支持的直接实例独立呈现，不因安装来源相同而合并开关；守护程序尚未核实的实例显示具体缺口，禁止同名扩杀。

详情显示确切配置／定义、PID、登录登记、真实操作阶段和失败代码。日志可在本地读取最近 64 KiB／200 行，Shou 启动输出与业务日志分开；日志读取失败不清空服务列表。进度只在当前实例显示一处主要指示，失败后保留行和刷新入口；未核实结果必须刷新后再操作。MySQL 专属数据库／账号／配置／日志／独立实例见[对应合同](mysql-administration.md)；端口健康、PATH 默认版本、别名、通用备注、编排、热重载和持续监控尚未接通。

Node 软件包元数据只证明包名与版本，不证明安装管理器。Bun、nvm 和 npm 的已知存储根分别标注存储来源；其他位置显示“Node 软件包”。来源胶囊不据此授予安装／卸载权限。

## 软件配置文件与日志

Mac 的 Nginx、Redis、PostgreSQL、MongoDB、Apache、Caddy、Meilisearch、Consul、etcd、Numa、Mailpit 已增加专属配置与日志任务入口。Platform 从确切本机实例、Homebrew 服务参数和各软件固定布局解析实际存在的文件；PostgreSQL 的数据目录不等同于安装目录。已观察安装可关联已有开发环境的数据根，存储中的配置仅为文件候选，不证明正在运行的服务使用它。发现与读取在后台进行，切换软件后丢弃旧请求结果。

支持用户选择明确文件，包括无扩展名 Caddyfile，以及 cnf／conf／YAML／TOML／JSON。不支持的格式可以读取但不开放保存。不展开 include、运行配置内容、提权或自动重启。共享文件适配器与 MySQL 共用拒绝链接、单链接普通文件、256 KiB 预算、身份／原文重查、锁、摘要意图、同句柄写回和结果核验。只修改当前用户可写且非其他用户可写的配置；运行中的本机直接实例先停止再保存。外部实例配置变更后的启动配方重新登记尚未接通，保存不等于获得重启资格。

Apache 的存储配置按原始程序路径摘要定位；Caddy 使用 Caddyfile；Meilisearch 与 Numa 使用 TOML；etcd 使用 YAML；Consul 使用已核实主版本的 JSON，版本未知时不猜文件。Mailpit 使用 MP_* 环境配置，不虚构 config 参数，读取 MP_LOG_FILE 时保留值中的等号。存储中的配置和日志均须实际存在，不自动创建默认文件。

Nginx 读取明确绝对路径的 access／error 日志，Redis 读取明确 logfile，Apache 读取明确的访问／错误日志，其他新增软件仅使用已核实存储布局或明确配置路径；各实例的业务日志与启动输出分开。PostgreSQL 日志轮转、MongoDB YAML 日志路径和 Nginx include 内日志尚无完整解析，不猜测路径。显示范围为最近 64 KiB／200 行，没有路径、文件不可读与空日志分别呈现。

日志页另有“清空日志”，在当前页面审阅确切路径及占用，由红色“永久清空”一次确认。Core 使用两分钟内有效的一次性计划、当前文件复查、变更租约、意图和结果；Native 对当前用户拥有且可安全写入的单链接普通文件原地截断，保留同一文件以供服务继续写入，不放入废纸篓、不保留恢复副本。新增内容、替换、链接、权限和意图记录失败均阻止变更；持续写入使结果无法核实则要求刷新，不自动重试。日志内容不写入操作记录，空间估算不承诺精确的系统可用空间增量。

已识别的 Homebrew 安装行直接提供卸载审阅，按软件包来源核实全部实际卸载版本；已知活动实例要求先停止，派发前另查当前用户在 Cellar／Caskroom 中运行的程序映像。此检查未完整覆盖复制到 Applications 的 cask 与其他用户进程，不能称为全机活动检查。静态／自定义版本目录删除和完整残留清理仍待接入。Windows 已接通同一日志清空领域合同与原生日志页；Nginx、MySQL、Redis 从实际存在的本地日志布局发现文件，其他工具可通过原生选择器指定日志。读取限制为最近 64 KiB／200 行，原地清空只接受当前用户拥有的普通单链接 .log／.err／.out 文件，固定祖先及文件句柄，拒绝 reparse point、受保护目录、替换、追加及写入占用；占用时先停止写入再刷新。不提权、不生成恢复副本。Windows 安装行新增精确 WinGet 来源的卸载审阅，安装器公开执行门禁仍关闭。专属配置写入和其他软件的自动日志路径仍待接通；原生结果以本次验收记录为准。
