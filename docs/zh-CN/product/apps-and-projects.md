# 应用与项目

[English](../../product/apps-and-projects.md) | 简体中文

“应用与项目”将应用、开发项目和启动项放在同一组导航中，围绕用户认识的对象组织任务。macOS 本轮已有应用列表、关联组件审阅、项目产物归组与共用规则选择，新增单来源的只读更新发现；自动安装、Git 远端状态调查和整个项目删除不在本轮实现范围。Windows 已有对应导航与项目产物页面源码；原生运行验收待完成。Windows 当前按共享内置规则的 build／dependencies 类别限制结果、推荐、全选及计划范围，独立保留页面选择；macOS 的项目标记归组、个人规则项目归属投影仍待补齐；更新发现已有独立 Windows 源码，不能宣称完全一致。

## 应用

应用本体、可核验的关联缓存与用户数据在同一行展开。每个组件保留确切路径、容量估算、归属与当前资格。运行中的应用、重复安装、共享组件和无法确认归属的内容继续遵循[应用卸载](application-uninstall.md)的独立合同。

应用残留从应用页进入；启动项作为同组的独立任务使用现有系统适配。视觉合并不把缓存规则变成卸载授权，也不把启动注册信息变成清理权限。

更新发现沿用应用行内明细，由用户主动查询单款应用的公开目录版本并打开官方入口；未知不显示为“已是最新”。来源、网络、版本和身份边界见[第三方应用更新发现](application-updates.md)，不与本产品自身更新混用。

## 开发项目

本地开发、自建项目和克隆项目共用扫描。来源平台不决定清理资格。Core 根据扫描已经观察到的清单标记，将同一项目下的构建产物和依赖归组；不能确认项目根时，界面明确“按扫描位置归组”。项目列表不另读源码正文、不执行 Git 网络请求，也不以远端存在为由认定内容可恢复。

容量标注为“匹配的清理项目”，仅汇总已经去重的候选，不能当作整个项目大小。构建产物、依赖和个人规则命中项按具体路径选择，源码目录、清单、锁文件和受保护数据仍保留。包管理器的全局共享缓存保留在智能清理的工具类别，不因选择一个项目连带选中整个共享存储。

智能清理与项目页共用候选身份和选择集合。项目页的按钮只准备项目来源的已选项目；智能清理底栏仍明确汇总其全部已选范围。搜索只改变可见列表，不授予新的权限。确认前继续去重父子路径并复核当前清单。

## 规则与执行

内置规则与明确启用的个人规则共用一个规则来源，不复制一份项目专用规则。自动推荐与手动审阅分开；手动审阅在准备阶段重新完整计量，不能拿扫描时的不完整清单直接执行。

默认清理为永久删除，确认准确路径和不可逆后果；选择废纸篓时使用独立动作名称，不宣称已释放同等空间。项目页不提供整项目删除、自动放弃 Git 改动或删除 worktree 的快捷动作。未来如需这些能力，必须单独设计未提交、未跟踪、未推送、共享对象和本地配置的影响合同。

## 验证

领域夹具检查项目归组、候选身份、容量去重与应用缓存分离；现有清理测试继续检查永久删除、保留源码、排除、变化后拒绝和无确认不删除。原生界面另行验证同组导航、展开、选择、容量反馈、项目范围审阅和取消。当前结果见 [SYNC.md](../../../SYNC.md)。
