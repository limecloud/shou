## 1. 用户目标与当前差距

用户应能在 Shou 内回答三个问题：主要空间用在哪里、哪些内容在自己的保留条件下值得处理、如何把这次判断复用为规则。一次调查可以产生规则，也可以得出保留或证据不足的结果。调查完成不等于已经清理。

| 范围 | 当前工作区事实 | 本轮产品要求 |
| --- | --- | --- |
| 模型连接 | 已实现默认关闭的总开关、原生表单、可开关决策服务、必需主模型及配置增删改查 | 新包的真实服务读取与全面状态验收独立跟踪 |
| 空间调查 | 共享启动面板、固定范围检查器、问答、证据、单条建议及用量已实现 | 质量校准与完整辅助功能组合待验收 |
| 多页面入口 | 智能清理、空间、大文件父目录及规则入口已接入同一协调器；外部工具独立标识 | 各上下文及冲突交互逐项绑定验收证据 |
| 规则闭环 | 生成夹具已走通原生调查、单条预览、新扫描、废纸篓回执及恢复 | 真实服务新包验收与夹具结果分开记录 |
| 任务恢复 | CLI 与两端桌面可打开本地记录、续接等待问询 | 原连接与 24 小时有效期保留；中断 running 任务不作为可续接记录 |

已实现持久化的桌面总开关，新安装默认关闭。用户为本机提供并要求配置模型，不改变其他安装的默认值。

## 3. 结构化决策优先的任务路由与费用

配置决策服务时，默认策略为「结构化决策优先」，当前使用 Jev：先由本地代码处理确定性问题，再把有足够证据、固定选项的判断交给 Jev；只有需要开放式语义理解、陌生生成逻辑或无法用模板表达的说明时才使用主模型。路由、受控问题和本地草稿模板已实现；可解决场景的主模型零调用通过合成合同验证。

| 任务 | 首选处理 | 升级或停止条件 |
| --- | --- | --- |
| 大小、排序、年龄、覆盖、精确路径、规则匹配 | 本地 Core | 缺事实则补扫描／显示未知，不交模型算数 |
| 已有证据的用途分类、已知模板选择、下一项受控取证 | Jev 固定 Choice | 证据不足先有界查询或问用户；仍需开放式理解时才升级 |
| 明确保留回答是否支持既定重建条件 | Jev 或本地明确字段规则 | `needs_information` 补证据，`retain` 保留；不以概率覆盖用户选择 |
| 精确目录与已知规则意图转成草稿 | 本地模板编译、Core 校验；必要时 Jev 选受控意图 | 只从已观察目录构造；不能让 Jev 编写任意规则 JSON |
| 已知结果的简短解释、问题和摘要 | 本地化模板 | 模板无法解释陌生用途／条件时才请求主模型 |
| 陌生语义、复杂保留条件、需要自由文本的解释 | 主模型 | 限定同一目标和证据；返回意图仍需本地校验 |
| 主模型给出新假设／较高风险草稿 | 按证据需要由 Jev 复核 | 不重复复核已经确认且未变化的同一证据；复核不是删除授权 |

每个可用方案必须配置主模型。设置用「启用决策服务」开关控制 Jev：开启为 `decision_first`，本地分析后由 Jev 协助主模型，足够的固定判断无需实际调用主模型；关闭为 `main_only`，由主模型接管，保留 Jev 配置和密钥。Jev 不能单独配置为可运行方案；旧记录可查看、编辑补全或删除。

开始前显示可能使用的全部目的地，调查中用「结构化判断」「需要主模型理解：原因」等真实阶段说明路由。同一已披露范围内的语义升级无需反复弹确认；切换到未披露服务、扩大范围或增加正文读取则需新的明确选择。Jev 网络／认证／格式错误直接显示失败，不因失败自动改用更贵模型；证据不确定和服务不可用必须分开。

结果及任务详情分别显示 Jev／主模型的实际请求次数、报告 token 和升级原因。无价格配置时仅展示用量，费用标为不可计算；兼容网关使用其实际计费，不能套用 OpenAI 官方单价或把 Jev 廉价当作质量证明。同一场景比较调用次数、总输入、耗时、费用与结果质量，不承诺未经测量的节省比例。

## 4. 开关、连接与联网行为

总开关使用「启用 AI 调查」，位于「设置 → AI 调查」。新安装默认关闭，显式开启后记住本机选择；保存连接、扫描磁盘或打开页面均不自动开启。连接为空时允许开启，但显示「添加模型连接」引导。

| 操作 | 应发生的行为 |
| --- | --- |
| 开启 AI | 显示功能、发送字段、服务目的地和可选 Jev 的说明；不自动发请求 |
| 关闭 AI | 立即禁止新的桌面模型／Jev 请求，取消当前调查和连接测试；保留部分结果、连接与凭据 |
| 关闭后查看结果 | 可离线阅读既有结果，查看已导入规则；继续调查／测试需要重新开启 |
| 关闭后使用规则 | 已启用规则照常本地扫描和清理；总开关不批量停用或删除规则 |
| 关闭后管理连接 | 可本地新增、编辑、保存；测试按钮说明需要开启 AI |
| 启用 Jev | 新调查默认选择 Jev 优先路由；明确可能使用的 Jev／主模型目的地与相对证据 |
| 关闭 Jev | 明确提示后续使用仅主模型策略；不删除 Jev 密钥，不改变当前任务快照 |
| 切换默认连接 | 只影响之后的新调查；当前任务仍显示原连接，禁止静默转发上下文 |

关闭无法撤回已送达第三方的请求，也不承诺抹除服务商记录。停止是停止任务，不是回滚。本地凭据不要求系统授权，旧钥匙串采用无交互访问；失败时在应用内引导改用本地存储。凭据返回后再次检查开关和取消状态。

总开关是桌面联网偏好，不代表吊销 API key 或系统网络权限。CLI 的显式 `ai` 网络命令使用自身调用授权，当前不读取桌面偏好；界面与帮助必须说明这点。离线命令、普通扫描、预览和既有清理不因开关改变。

## 5. 页面入口与范围

内置功能统一叫「AI 调查」；具体动作用「调查此文件夹」「调查所在文件夹」「用 AI 制定规则」。外部路径统一标识「外部 AI 工具」，不再让同名「通过 AI 定制」同时代表两种不同流程。

| 页面／位置 | 可见入口 | 传入的范围与专用交互 | 本轮状态 |
| --- | --- | --- | --- |
| 设置 | 启用 AI 调查、配置列表、添加／编辑／删除／恢复／测试 | 开关、目的地、协议、模型、凭据、Jev 及测试结果 | 已实现；默认关闭及独立 Jev 表单已观察 |
| 智能清理空状态 | 用 AI 调查文件夹… | 原生目录选择；说明先测量，再由用户开始联网调查 | 已实现；上下文完整走查见验收矩阵 |
| 智能清理结果 | 调查其他占用…；具体路径菜单「调查此文件夹」 | 显式目录，不扩大到整个主目录；清理快照不能冒充空间索引 | 已实现；上下文完整走查见验收矩阵 |
| 空间分析空状态 | 扫描后使用 AI 调查 | 选择目录和本地扫描；不显示无效的开始调查按钮 | 已实现本地扫描引导 |
| 空间分析结果 | 工具栏 AI 调查；目录行／树图菜单 | 当前目录或具体子目录；主界面仍可浏览，调查范围固定 | 工具栏、目录行及图菜单已实现 |
| 大文件结果 | 调查所在文件夹 | 单个文件的父目录；先在启动面板明确显示父目录 | 已实现；上下文完整走查见验收矩阵 |
| 清理规则 | 用 AI 制定规则… | 明确目录及所需保留条件；新建禁用草稿 | 已实现内置与外部独立入口 |
| 个人规则详情 | 审阅、预览、启用并扫描 | 显示原调查依据；修改规则另存禁用版本，不覆盖已启用版本 | 已接入独立预览和既有规则链 |
| 应用卸载 | 帮助理解此组件 | 需要确切应用身份、组件类型、共享／个人数据及运行事实 | 后续专门适配，当前不接入 |
| 启动项 | 帮助理解此项 | 需要来源、签名、注册及状态证据；现有控制确认独立 | 后续专门适配，当前不接入 |
| 隐私清理 | 说明此清理项的影响 | 仅来源、类别、时间范围与聚合数，不上传历史条目／Cookie 值 | 后续专门适配，当前不接入 |

跨页面入口共享一份调查任务与检查器，不为每个页面创建聊天窗口。已有索引覆盖相同目标且仍有效时复用，否则先进行本地空间扫描。需要扫描、已有任务、已关闭或未配置时，显示相应原生面板及明确下一步，不能只弹通用错误。

从其他页面进入时，启动面板先显示目标目录、使用的连接、是否重用测量及下一步。若已有运行／等待中的调查，用户可「返回当前调查」或「停止并新建」；关闭面板不丢弃当前任务。新目标不能静默替换当前范围。路径变化、扫描失败或用户取消选择器时留在原页面并保留原状态。

## 6. 端到端用例

### UC-AI01：第一次开启和配置

前置：新安装，AI 关闭，无连接。

1. 用户从设置或页面内 AI 入口进入启用说明。
2. 用户开启开关，查看传输范围；此时没有模型请求。
3. 在同一方案中配置必需大模型与可开关决策服务，分别填写地址、模型和密钥。默认采用结构化决策优先策略，macOS 密钥使用本地私有存储。
4. 「测试连接」发送合成数据，分别显示主模型工具往返与 Jev 测试结果。
5. 用户保存连接并选择用于后续调查。

分支：取消不保存表单内容；保存失败保留输入并提示。日常保存、测试、调查和续查不弹登录钥匙串密码框；旧配置可改用本地存储并重填一次密钥。测试成功必须与当前配置绑定，修改后清除成功标识。

后置：保存无密钥连接引用；没有上传真实目录或执行清理。

### UC-AI02：从智能清理调查未覆盖空间

前置：常规扫描完成或用户尚未扫描。

1. 用户点击「调查其他占用…」或「用 AI 调查文件夹…」。
2. 选择明确目录，确认使用范围；需要时先完成只读空间扫描。
3. 进入共享调查工作区，查看范围、覆盖情况、模型及 Jev 目的地。
4. 用户说明保留条件，单独点击「开始调查」。
5. Agent 优先查询最大相关分支，保留未解释项，不仅返回固定小缓存。

分支：目录不可读时说明缺口并可换目录；关闭 AI 或无连接时先显示设置引导；不把稀疏清理扫描转换成虚假的完整测量。

后置：调查结果与实际空间索引绑定；本次未选择任何清理目标。

### UC-AI03：从空间图调查某个陌生目录

前置：存在有效空间快照。

1. 用户在目录行或树图选择「调查此文件夹」。
2. 检查器显示固定目标、相对证据字段及服务；用户仍可浏览其他目录。
3. 开始后展示真实阶段、已查询证据数和步骤，不伪造百分比。
4. 用途不能确定时提出具体问题，用户可选答案或自由回答。
5. 回答后继续原调查，保留原连接；展示完成、保留、补证据或未完成原因。

分支：刷新扫描或清理改变文件状态后，结果标为过期，要求新调查；切换目录不悄悄改变运行任务。

### UC-AI04：从大文件调查其目录

前置：大文件列表中存在测量结果。

1. 用户对单个文件选择「调查所在文件夹」。
2. 启动面板明确显示父目录，说明只使用目录元数据，不读取或判断文件正文。
3. 用户确认范围；复用有效索引或先本地扫描，再按 UC-AI03 开始。

分支：多个文件分属不同父目录时不自动扩大到共同祖先，应要求选择一个目录。单个视频、归档或模型权重不能仅凭大小判定为可删除，也不能伪装成可重建目录规则。

### UC-AI05：独立规则到清理回执

前置：调查已形成一条或多条建议。

1. 用户查看每条的精确目录、观测容量、用途假设、重建条件和限制。
2. 选择一条「预览此规则」，导入默认禁用草稿，执行实际文件匹配。
3. 原生预览显示命中、保护、不满足条件和相对已启用规则的新增收益。
4. 用户可保持禁用；或「启用并扫描此规则」，进入当前文件的清理结果。
5. 用户选择实际项目和动作，通过既有具体范围确认后执行。
6. 回执显示已处理、跳过、失败或未知；可用容量变化与估算分开。

分支：零命中提供检查条件／重扫入口；保护项说明原因；过期证据不能继续预览。预览、开启 AI、Jev 支持判断均不等于删除确认。其他规则保持原选择。

### UC-AI06：调查中关闭 AI、取消或失败

1. 用户点击「停止调查」或关闭总开关。
2. 界面立即进入停止请求状态，阻止继续及重复启动，取消网络与后续步骤。
3. 保存已确认的证据和建议，最终显示取消或实际失败状态。
4. 关闭时只读查看结果；重新开启后，可用明确的新调查入口继续工作。

失败分支：认证错误去编辑连接；网络／超时允许新调查；超预算说明已结束及已有结果；不自动重试、不自动换服务。当前只支持等待问答的服务续接，不能把失败／取消任务的「重新调查」误称为原步骤恢复。

### UC-AI07：Jev 优先处理与按需升级

1. 用户先配置主模型，再配置并开启 Jev；方案默认采用「结构化决策优先」。
2. 开始前看见全部可能目的地；本地先完成计量和范围判断。
3. 固定选项的分类、取证选择和重建判断由 Jev 完成；本地模板足够时直接形成解释或禁用草稿，不调用主模型。
4. 需要开放式理解时显示升级原因，才调用已披露主模型；新假设按需再由 Jev 复核，不对不变证据反复付费。
5. `supported` 只支持草稿审阅，`needs_information` 补证据，`retain` 保留；结果展示各模型实际用量。

分支：Jev 错误使调查明确失败并保留已有结果，不自动转发给主模型。用户可修复或明确改策略后新建。缺少主模型的旧配置必须编辑补全才能启动或继续调查。该路由及分服务用量已实现，合成场景通过；真实质量和费用对照仍待校准。

### UC-AI08：下次离线复用

前置：用户已审阅并启用个人规则。

1. 关闭 AI 或断网后，用户运行日常智能清理。
2. 既有规则参与本地新扫描；禁用草稿不参加。
3. 用户确认当前具体范围，执行并查看回执。

后置：复用的是规则条件和明确选择，不是上次的模型请求、路径清单或删除授权。

## 7. macOS 界面与完整状态

设置遵循原生分组：首行功能说明和开关；开启后显示默认连接及连接管理；关闭时保留可查看的配置，明确网络动作不可用。连接编辑使用 Form 和 SecureField，避免把网关协议或调试字段塞进调查结果。

调查工作区采用可调整右侧 inspector：顶部固定任务名称与关闭按钮，内容从范围／连接／披露进入问题与结果，底部显示当前主要动作。关闭 inspector 不停止任务；再次打开能看见当前状态。运行中更换目标需明确选择；窗口退出或有未提交回答时需提供相应离开提示。

| 状态 | 显示内容 | 主要操作／恢复路径 |
| --- | --- | --- |
| AI 关闭 | 功能简介、不开启也可本地清理、旧结果可读 | 开启 AI；前往设置 |
| 未配置 | 需要支持工具调用的模型连接 | 添加连接；取消返回 |
| 无扫描 | 目标目录和本地测量说明 | 选择目录；扫描 |
| 本地扫描中 | 实际路径、计数、覆盖及可取消进度 | 停止扫描 |
| 就绪 | 固定范围、测量时间／完整性、服务目的地、保留输入 | 开始调查；编辑连接 |
| 运行中 | 当前阶段、步骤、证据数和原连接 | 停止调查；关闭检查器仍保留任务 |
| 等待回答 | 原子问题、选项、自由回答与长度限制 | 继续调查；停止；缺答案时说明原因 |
| 正在停止 | 已请求停止；仍等待系统返回时准确说明 | 禁止重复继续；保留结果 |
| 完成有建议 | 摘要、证据、逐条规则、Jev 判断 | 单条预览；新调查 |
| 完成无建议 | 明确保留原因、证据缺口或后续诊断 | 新调查；查看证据；返回浏览 |
| 失败／超预算／取消 | 真实原因、已有结果、未调查范围 | 编辑连接或新调查；不显示成功标识 |
| 结果过期 | 扫描或文件状态改变 | 重新扫描／调查；禁用旧建议预览 |
| 规则预览中 | 实际本地匹配进度 | 停止；保留禁用草稿 |
| 规则预览完成 | 命中／保护／零命中、新增收益及条件 | 保持禁用；启用并扫描；检查条件 |
| 清理完成 | 当前回执与逐项结果 | 查看历史、允许时恢复或重新测量 |

错误显示原因和可执行下一步，不显示服务端原始正文或密钥。输入限额就近说明，保留用户已输入内容。结果较长时保持主体可滚动，底部操作不挤出窗口；窄窗口、长路径、中英文和深浅色均要走查。

键盘可到达开关、连接、问题与建议；SecureField 有明确标签；Esc 关闭非运行表单或走相应停止／离开流程；VoiceOver 能区分运行、等待、停止和失败。状态变化来自事件；遵循减少动态效果，不能用模型字数制造进度。

原生设计参考：[Toggles](https://developer.apple.com/design/human-interface-guidelines/toggles)、[Inspectors](https://developer.apple.com/design/human-interface-guidelines/inspectors)、[Progress indicators](https://developer.apple.com/design/human-interface-guidelines/progress-indicators)、[Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility)。这些是设计依据，不构成已通过辅助功能验收的声明。

## 8. 成功指标与交付条件

用同一生成／经同意脱敏场景比较内置与外部流程：首次可完成率、手动交接次数、主要占用的可解释范围、错误建议、无依据断言、追问负担、完成耗时和实际报告用量。模型报告 token 是观测值，停止阈值不是精确费用上限。

P0 交付须覆盖 US-AI01–US-AI14 与 US-AI17 的正向与异常路径，尤其关闭时零新增请求、跨页范围一致、无建议时可理解、单条规则到既有回执的下一步。现有测试不能替代新开关和入口测试；逐项状态与证据以[验收矩阵](../engineering/embedded-ai-acceptance.md)为准。

## 9. 决策服务提供方与切换

结构化决策是一项能力，Jev 是当前首个实现。设置显示实际提供方、地址、模型和处理策略，不把产品能力永久命名为 Jev。未来提供 Clef 等适配器后，可在同一连接编辑器选择；当前只列出已实现的 Jev，不展示虚假的可用服务。选择新提供方后重新配置并测试其凭据，旧凭据不自动跨服务复用，已有任务不被迁移或重发。

用户故事 **US-AI17**：作为希望控制成本和服务选择的用户，我希望替换结构化决策提供方，同时保留相同的调查、证据与规则审阅流程。验收要求：路由依赖统一合同；可注入替代适配器完成同一固定判断；当前默认 Jev；旧连接可读；未知适配器明确不可用；切换不影响运行任务或清理权限。

### UC-AI09：独立 CLI 调查与取消

1. 通过 `capabilities --command ai` 和 `ai providers` 发现真实能力，保存不含密钥的连接。
2. 使用标准输入配置系统凭据或明确指定环境变量；合成测试验证目的地。
3. 本地扫描后 `ai investigate`，通过 `ai list`／`ai show` 查看原范围、问题、实际用量和建议。
4. 以问题 ID 提交回答并 `ai resume`；或另一进程 `ai cancel`，原进程停止在途请求与后续步骤。
5. `ai advice import` 只导入一条禁用草稿；预览、启用、重扫及当前范围终端确认继续使用既有合同。

### UC-AI10：Windows 原生调查与重启续接

1. 在 AI 页面开启默认关闭的开关，通过原生连接表单独立配置主模型与 Jev；测试仅发合成数据。
2. 从清理、空间目录、大文件父目录或规则页进入，确认精确目录、目标、连接及发送字段，再明确开始。
3. 没有可复用索引时先本地测量；等待中保留回答，切换标签页不改变范围；关闭开关取消请求。
4. 查看证据、结构化判断、服务用量与升级原因，选择单条草稿进入现有规则预览和清理确认。
5. 退出提示未提交回答不会保存；重启后本地列表可打开已保存问题，以原连接在有效期内续接。过期、缺索引或运行时不兼容明确要求新调查。

Windows 的交叉编译、原生 CI、真实 WPF 交互是不同证据。CLI 与桌面共用业务服务，界面偏好不会暗中覆盖显式终端网络授权。

## 凭据、协作方案与范围的交互补充

作为日常使用者，我希望保存一次 Key 后，桌面、连接测试、调查续接和 CLI 都能直接使用，升级应用不再弹登录钥匙串密码框。macOS 默认本地私有存储；旧配置通过应用内入口重填一次后迁移。密钥不进入公开连接资料、历史、导出或日志；文件权限保护与系统凭据加密的区别在表单说明。

作为需要控制费用的用户，我希望在同一个方案中看见 Jev 和大模型各自职责、模型和目的地。下拉项显示实际组合，详情标注「优先」与「按需」；关闭 Jev 时只展示主模型，展示与实际调用一致。默认新建方案包含主模型与决策服务，主模型为必需项，Jev 可独立开启或关闭。

作为正在浏览磁盘的用户，我希望能明确选择全部扫描范围或一个目录。空间页带入单个勾选目录，其次是高亮目录，再次是浏览目录；启动面板可切换全部已扫描范围或单个目录，并通过原生选择器更改。全部指当前索引根及其子目录，不暗中包含其他卷。取消不改变任务，调查范围不改变清理勾选。确认路径后先本地测量或复用索引，再由用户开始联网调查。

达到限制时显示具体原因、已有证据与下一步。时间上限不计凭据加载与用户回答等待；token／步骤／决策请求／工具／证据／响应大小和概览目录上限分别说明。内部停止不表示第三方账户余额不足。旧记录缺少限制原因时保留原有事实，不推造用量。

### UC-AI11：管理配置并切换 Jev

1. 在设置中新建命名方案，填写必需主模型；可同时配置 Jev，两个服务的地址、模型和凭据独立。保存只写本地。
2. 列表显示名称、实际服务组合及默认项；用户可查看、编辑和设为默认。主模型字段始终可见，不能关闭。
3. 关闭「启用决策服务」，新调查直接使用主模型，不读取 Jev 凭据、不发送 Jev 请求。Jev 的原配置和密钥保留，之后可重新开启。尚未配置 Jev 时，开启操作先打开编辑器完成配置。
4. 编辑时密钥留空表示保留已存密钥；修改表单会清除原测试成功状态。连接测试只验证启用的服务。
5. 删除前显示方案名称和可恢复说明。确认后从可选配置中移除；若为默认项，选择另一个完整方案，没有则显示配置引导。取消删除保持原状态。
6. 在「已删除配置」恢复后，该方案重新可用，原凭据及历史不变。已删除配置禁止直接编辑、测试和启动；先恢复后操作。
