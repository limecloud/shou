## 2. 产品判断

- 基础清理、空间图、应用卸载、启动项和 CLI 已有实现。下一版本优先完成质量与验收，不重复建设批量卸载、管理员应用移入废纸篓或启动项开关。
- 高价值数据的专用处理、第三方应用更新、系统监控与常驻工具属于不同扩展方向，按用户收益和实现边界分别排序。规则数量不能代替实际可回收容量、准确性或兼容性。
- 持续投入开发者空间调查、可复用个人规则、GUI／CLI 一致执行，以及可核验的计划、结果和恢复。价值以用户完成任务的结果衡量。
- “AI 工具数据清理”管理工具产生的数据；“AI 调查”借助模型解释占用并提出禁用规则草稿。两者职责独立，不能以一个能力的实现替代另一个。

界面实施沿用最新工作台：顶部主导航和次级任务、青绿至冰蓝的全窗口背景、原创任务插画、开阔内容区、全宽对象行与行内展开、稳定的选择底栏。新诊断放在设置的支持分组，空间比较放在分析操作菜单；后续更新发现和专用审阅归入现有对象任务。尺寸与配色以共享 token 为准，不恢复旧侧栏、密集小字或额外并列导航。Windows 分别实现和验收，资源生成不代表新布局已落地。

新增能力按以下位置承接；“规划”表示尚未交付，不能先放置无效按钮。

| 工作包 | 页面落位与交互要求 |
| --- | --- |
| NV02 开发者覆盖 | 智能清理及“应用与项目 → 开发项目”；复用候选和选择，在对象行内展示路径、重建代价及不可选原因，底栏只汇总当前任务范围 |
| NV03 原因与诊断 | 失败／部分结果就地解释；设置的支持分组打开只读诊断，可展开、复制及重试，不自动发送 |
| NV04 AI 调查 | 沿用现有调查入口和独立草稿审阅；启用后返回当前任务重扫，保持调查状态与删除选择分开 |
| NV06 空间比较 | 空间分析操作菜单打开独立比较视图；历史、覆盖和变化就近展示，关闭后保留原导航与选择，不生成清理选择 |
| NV07 更新发现（实施中） | 应用对象行内显示目录版本、来源和官方入口；沿用应用搜索与展开，不新增顶级更新中心 |
| NV08 专用审阅（规划） | AI 旧版本先落到智能清理的对应工具明细；安装包先落到大文件的专用筛选与明细，两条链路分别设计和验收 |
| NV09 残留与补全 | 残留沿用应用页入口与关联组件审阅；补全由 CLI 输出静态脚本，不增加图形配置页 |

所有新视图沿用现有空、加载、部分、失败和完成状态组件。列表出现后优先展示工具栏与数据；插画用于初始页或紧凑标题。验收覆盖当前最小窗口、中英长文案、深浅色、减少动态效果及键盘焦点；尺寸仅引用[设计规范](interface-design.md)和共享 token。

## 4. 保留并验证的现有优势

1. **个人规则闭环**：调查、必要追问、单条禁用草稿、独立预览、启用后重扫，再确认当前计划。收益是把个人目录知识变成可复用策略，而非每次重新询问模型。
2. **单平台 GUI／CLI 一致性**：共用领域服务、变更锁和历史，减少入口间策略漂移；通过并发夹具验证锁、状态和结果一致性。
3. **可核验的执行结果**：身份与清单绑定、过期与防重放、意图先行、部分／未知结果、已验证废纸篓项恢复。下一版本应把这些能力转化为易理解的结果。
4. **模型与变更隔离**：常规清理离线运行，AI 可关闭，规则不能提供任意命令。开发者工具仅使用固定本地操作；不扩大为 Shell 执行框架。
5. **结构化隐私清理**：已有按来源和时间范围的专用合同，Cookie 同意独立、未知数据库结构保留。它是已有资产，需准确披露兼容范围，不以文件夹清理代替结构验证。

## 5. 下一版本建议范围

v0.15.0 纳入最新工作台及 NV03 的诊断、NV06 空间比较、NV07 只读更新发现和 NV09 的静态补全；NV01–NV05 的剩余验收逐项保留，Windows 以关闭公开变更能力的受限预览交付。NV08 专用审阅和 NV09 残留扩展保留后续候选。P2 项目不进入本轮交付承诺。每个工作包沿用现有小型能力接口，不建设通用插件、维护任务或更新器框架。

### NV01：冻结可发布基线与兼容性矩阵（P0）

- **问题**：部分产品文档仍描述早期能力；工作区已有新实现，但全套回归、原生 UI 和发布证据并不齐全。
- **范围**：逐项核对实际二进制能力、所属合同和 SYNC；对已实现的卸载、启动项、隐私及 AI 标注准确状态；先建立代表性应用／开发场景矩阵，再按风险补样本。
- **责任模块**：现有 `tests/core`、平台测试与 CLI 验证脚本、验收文档和 `SYNC.md`；不重复实现已有服务。
- **验收**：每个宣称支持的场景记录平台、架构、应用版本、范围、执行命令及结果。规则声明数、生成夹具数、真实应用观察数分别统计。未解决失败保持阻断；宿主进程预算导致的拒绝有可重复的受控环境验证，不放宽活动门槛。

### NV02：提高开发者清理的有效覆盖（P0）

- **问题**：用户关心大目录是否找得到、为何不能选、删除后需付出什么代价，而不是模板数量。
- **范围**：优先验证 Rust `target`、Swift `.build`、Node 构建目录及依赖、Xcode／包缓存、现有 AI 工具缓存；对漏检、有限深度、宽目录和活动未知分别给出原因。新增具体缓存须有可重建证据。
- **责任模块**：`NativeCleanupDiscovery`、Core 的 `Rules`／`ArtifactSafety`、共享规则与位置 JSON、智能清理页面；Windows 按其独立实现验证。
- **验收**：每个选定场景具备应命中、应保留和扫描后变化三类生成夹具；源码、凭据、手改依赖、私有包、活跃构建及持久状态保留。永久清理确认、回执和无关文件哈希均正确。报告实际命中容量与未覆盖原因，不设无证据的“多清理若干 GB”目标。

Windows 已增加独立 `CleanupScanner`，供 GUI／CLI 先发现规则目标、再公平分配完整计量预算；计划与预检定向重查所选范围和项目上下文。整树与规则范围的完成状态分开，稀疏观察不能进入空间比较。生成夹具和实际原生验证以 [SYNC.md](../../../SYNC.md) 为准；真实软件覆盖、活动矩阵和普通用户 Windows 11 仍按本工作包继续验收。

Windows Rust 生成源码已补充[精确内置定义、布局及实时 Git／活动合同](rule-coverage.md#windows-rust-产物)，不放宽个人规则或其他语言源码保护。Swift、Node 和 Cargo 解包源码的专用例外继续保留为未完成项；纯 .NET 与原生测试证据分别记录。

### NV03：扫描可信度、诊断与结果解释（P0）

- **问题**：已有保护策略和结构化错误，用户仍可能只看到扫描失败或不可选，无法采取下一步。
- **范围**：把权限、磁盘不足、活动未知、证据变化、部分覆盖分别呈现为明确原因与下一步；提供可预览、可复制的只读诊断摘要，复用现有历史和状态。没有可恢复证据时不显示恢复成功。
- **责任模块**：Core 状态／历史摘要、Platform 有界只读观察、macOS／Windows Presentation；UI 不重新判断删除资格。
- **验收**：中英界面覆盖原因、路径、重试或重扫入口；报告默认不包含个人绝对路径、用户名、会话正文、凭据、进程参数或环境值，不自动上传。低磁盘索引写入／封存失败、权限拒绝、停止和迟到回调保留真实状态；旧分析不被失败的新扫描覆盖。

### NV04：完成 AI 调查的用户闭环（P0）

- **问题**：已有调查实现，需要证明它能围绕主要占用提供可执行且可复用的结论，而非停留在展示模型回复。
- **范围**：收尾现有 macOS 调查、问答、独立规则、预览、启用后重扫及结果核验；AI 工具数据生命周期管理作为独立工作包规划。Windows AI 仍按独立 .NET 实施计划安排。
- **责任模块**：`packages/shou-ai`、Core 的调查／草稿服务、现有 AI UI 与 CLI；使用[既有 AI 验收矩阵](embedded-ai-acceptance.md)，不另立一套接口。
- **验收**：标注案例中的主要占用均有清理／可选／保留／待调查结论及依据；信息不足明确追问。确定性或决策服务已足够的案例不调用主模型。关闭、取消、超时与断网保留真实结果；生成目录完成单条草稿到确认执行及回执的原生旅程。真实服务只使用明确授权的合成证据。

### NV05：原生使用与分发验收（P0）

- **范围**：只为本次实际宣称支持的能力、系统和架构取得安装后原生证据；macOS 与 Windows 分别退出，不以一个平台通过替代另一个。
- **macOS**：验证已安装应用的扫描、选择、取消、卸载、启动项、隐私、历史及恢复；覆盖中英、深浅色、长路径、最小窗口、键盘与 VoiceOver。核对正式下载、更新订阅及升级后的数据保留；Developer ID／公证未完成时继续明确分发限制。
- **Windows**：MSI 上下文修复、计划任务回读和隐私 AppData anchor 兼容已在 Windows Server 2025 x64 生成夹具验证；继续取得普通用户 Windows 11 复验、原生选择器和被阻断的后续 E2E。磁盘／大文件、隐私、卸载与启动项逐条取证，验证停止／关窗与重启后记录。ARM64 运行、签名、安装／更新按原生方案分别取证。
- **责任模块**：现有原生适配器、UI、`scripts/windows`、打包／更新脚本和 [Windows 方案](windows-native-plan.md)。
- **验收**：Windows 未通过的变更能力不能进入正式可用承诺；若仍以受限预览交付，二进制必须实际关闭未验收能力，能力发现、界面、文档和附件一致。测试计数包含实际跳过项，不能把跳过的 MSI／任务专项当成功。所有删除只用本次生成夹具。

### NV06：空间增长解释（P1，优先增量）

复用已有不可变扫描和索引，先支持用户主动比较同一根目录的两次分析，列出主要增长目录、计量时间和覆盖变化。根身份、容量口径或覆盖不可比时明确拒绝结论，新增／缺失不能直接称为增长／删除；不默认后台全盘扫描，不把历史索引转换为当前删除资格。先验证分页、硬链接及稀疏文件计量、部分覆盖、索引清理后的失效和有界存储，再考虑日常提醒。

### NV07：第三方应用更新发现（P1，实施中）

macOS 首个来源为 Homebrew Cask 公共目录，确切映射六种稳定版应用；Windows 首个来源为 Visual Studio Code 官方稳定发布目录，使用独立注册身份匹配。[更新发现合同](../product/application-updates.md)拥有网络、版本、身份和官方入口语义；实现与验收分别记录。

- **范围**：首个小链路只选一种可验证来源，展示当前／可用版本、来源和官方入口，不执行下载包或替换应用。无可信元数据、渠道／架构不匹配、版本含糊时显示未知。
- **责任模块**：Core 更新观察模型、Platform 单来源有界只读查询、应用盘点及应用页行内明细；与 Shou 自身 `AppUpdater` 分开。
- **前置与验收**：先冻结来源、身份和版本比较规则；验证离线、超时、重定向、错误频道、错误架构、无效版本及取消，失败不误报“已是最新”。明确展示联网动作及其来源，不上传应用清单；只有用户选择可信入口才打开外部页面或应用。
- **后续边界**：单来源身份、下载完整性、签名、运行中应用、取消与失败处理完成独立设计后，才扩展为自动安装。

### NV08：AI 旧版本与安装包审阅（P1，后续候选）

- **范围**：拆成可独立交付的两个小链路：一种 AI 工具的旧版本、一种来源的安装包。先做只读发现，展示路径、所有者、版本／时间、用途、重建代价及不确定性。存在运行引用或无法证明闲置时保留。
- **责任模块**：Platform 固定位置与元数据发现、Core 分类与保护、共享声明及现有对象列表；不引入通用归档执行器或维护框架。
- **验收**：旧版本必须核对当前版本及运行引用；安装包必须有来源和格式证据，不能仅按扩展名归类。生成夹具覆盖当前版本、链接、坏归档、权限拒绝、预算截断和扫描后替换；不运行包内程序、不展开归档到用户目录。无法读取不显示为 0 或可清理。
- **后续边界**：删除走独立明确选择与现有计划／确认／回执；旧会话、worktree、记忆／技能、模型和 SQLite 数据不进入该缓存／旧版本工作包。

### NV09：专用卸载覆盖与 CLI 补全（P1，独立候选）

卸载以单款真实应用的明确残留合同为单位扩展，优先保留共享组件、其他安装副本和个人数据；工程验证只使用生成数据及隔离测试环境。CLI 先从现有命令定义生成帮助／补全，不手工维护另一套命令语义。两项可独立交付，不因同属 P1 而捆绑。

- **责任模块**：现有应用／残留领域服务和原生归属适配；CLI 命令发现定义与补全生成器。
- **验收**：残留样本记录应用版本、安装来源及确切组件，具备应保留的共享／重名／活跃反例。补全核对命令发现、参数、枚举、含空格路径与不可信输入；不在补全过程启动 Shou，不修改 Shell 配置，Bash／Zsh 的语法与真实交互分别记录。

## 6. 本轮不纳入的方向与安全边界

- 不新增无人值守删除、`--yes` 破坏性绕过或默认清空整个废纸篓。日常清理默认永久删除；应用卸载默认废纸篓，均沿用所属精确范围确认。
- 不增加通用 root 清理、内存清理、“一键加速”、风扇／电池写入、sudo 配置修改、应用二进制瘦身或虚拟磁盘内部文件删除。
- 不把会话、worktree、技能、记忆、模型和数据库当缓存删除。未来专用生命周期功能须先修改其所属产品／安全合同，并独立验证保留、活动检查、恢复边界与原生行为；本计划不授权这些变更。
- 不为对齐功能数扩建系统监控、托盘工具集、多更新源框架或 Windows AI 空壳。先交付可独立验收的小链路。

## 8. 开发与验收执行

顺序：NV01 固定范围和失败清单 → NV02／NV03／NV04 各自交付完整小链路 → NV05 核验同一候选构建 → 有余量再纳入 NV06。新的功能修改仍需同步所属中英文合同、必要的共享资源及 `SYNC.md`；本文只维护取舍和工作包。

| 检查 | 使用条件与证据 |
| --- | --- |
| `python3 scripts/verify-docs.py` | 文档链接、双语文件、标识及代码块；本计划文档变更的必要检查 |
| `python3 scripts/update-localizations.py --check`、`python3 scripts/generate-windows-resources.py --check` | 修改文案／共享声明后检查唯一来源与生成一致性 |
| `sh scripts/test.sh` | 修改 macOS 行为后按仓库常规范围执行；部分 CLI 检查会永久移除自行生成的夹具 |
| `sh scripts/test-windows-core.sh` | Windows 纯 .NET 领域／状态检查，不能证明原生系统或 UI |
| 原生系统、UI 与分发检查 | 精确记录实际命令、源码／资源版本、OS、架构、通过／失败／跳过和证据路径；Windows 集中验收遵循仓库云测试技能，开发期间保持云电脑关机 |

额外原生规则目录永久移除检查 `--native-trash-purge` 仍需明确授权。MSI 和计划任务专项只接受本次生成夹具，分别按仓库规定显式启用。普通文档更新不触发删除测试、云电脑启动或发布。

完成标准：所选工作包有真实结果和限制，用户能判断“发现了什么、为什么可选、会影响什么、实际处理了什么”，且下一次可复用同一规则重新扫描。未通过的能力继续显示不可用，不以更多页面或更多规则替代交付证据。
