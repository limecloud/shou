# 系统授权与逐项执行

[English](../../engineering/system-authorization.md) | 简体中文

状态：两端已有源码及可移植检查；本轮原生 Windows、UAC 和实际界面证据另行记录，编译不能替代原生验收。

Core 声明最小授权接口，Platform 维护进程期会话。macOS 使用系统认证和私有 Unix socket；Windows 使用 UAC 和带 ACL 的本地命名管道。两端均验证对端 PID、进程出生身份、可执行路径、随机握手及协议版本。密码界面由系统提供，不保存密码，不安装常驻服务。退出进程或通道失效后会话结束；已派发请求不自动重连或重放。

同一次 Shou 运行内，各功能复用已建立的管理员会话，不按项目或操作再次认证。协议 v2 使用严格递增的请求序号，以固定内存拒绝重放和乱序；取消绑定相同请求 ID 与序号。会话不再因累计达到 10,000 次请求退出，单次消息与操作预算仍保持有界。首次请求可以发起系统认证；取消、认证失败或已建会话失效后，后台任务及后续项目不自动再次弹出密码／UAC 窗口，仅用户主动点击授权入口时恢复。重新启动 Shou 需要建立新会话，此合同不承诺跨进程或跨重启保留管理员权限。

授权能力与本次业务确认分开。协议仅接受固定类型的操作，不接受任意命令、SQL、脚本或业务存储路径。Windows 支持提权的文件身份／目录读取、原位置权限核验、确切清单清理、MSI 卸载与当前用户计划任务控制；MSIX 仍在原用户上下文处理，其他账号的用户安装不会因输入管理员凭据变成当前用户安装。公开清理、系统卸载、启动项和隐私门禁仍受现有 Windows 验收状态约束。

清理执行先核验计划结构、摘要、当前确认、期限、来源绑定、配置与重叠范围；每项开始前复核该项身份、完整清单、归属、排除和活动状态，持久化意图后执行并记录结果。单项失效或已知权限／I/O 失败继续独立项；结果未知、日志失败、全局范围失效或用户取消停止后续。隐私每个来源保留独立数据库事务；历史恢复逐项核验且禁止覆盖。取消不能撤销已完成项，授权成功也不重试旧清理计划。

| 功能 | 权限与范围处理 |
| --- | --- |
| 智能清理、项目产物、应用残留 | 共用文件能力；规则、所有权、完整清单、活动与排除仍由领域层约束 |
| 空间分析、大文件 | 共用有界读取与清理；不可读项保留覆盖缺口，授权后重新扫描 |
| 应用扫描与卸载 | macOS 支持缺元数据的应用包单独审阅及管理员应用包；Windows 保留确切 MSI／MSIX 安装身份，未知安装器不变成文件删除 |
| 操作记录、恢复、后续永久清理 | 共用文件能力，读取记录不授予恢复权限；未知结果不重放 |
| 隐私数据 | 按来源执行、事务回滚与计数核验；macOS 完整磁盘访问单独引导，保护排除不冒充管理员权限问题 |
| 启动项 | macOS 系统 daemon 与 Windows 当前用户计划任务复用会话；系统管理来源与其他账号保持保护 |
| 开发工具配置与服务日志 | macOS 固定配置／日志位置按确切身份授权读写，日志截断保留文件；Windows 尚未接入的软件专属能力保持未实现 |
| 软件更新、工具安装／卸载、拥有者缓存命令 | 保留包管理器自己的执行与认证边界，不将 Homebrew、mise、Docker 或任意命令提升为 root；Windows WinGet 沿用系统安装器流程 |
| MySQL 与其他数据库管理 | 数据库账号、密码和授权属于数据库会话，不能用操作系统管理员权限替代 |
| AI 配置与凭据、监控、规则和记录维护 | 使用现有凭据库与用户私有记录；只读观察不授予进程控制或数据删除权限 |

完整磁盘访问、管理员身份、文件夹选择、数据库凭据与工具自身登录是不同能力。界面按实际错误提供入口；系统保护、身份变化、云占位及未实现能力不能用授权按钮掩盖。共享资源与模拟测试不证明 Windows 原生 UAC、ACL、WinUI、安装或 ARM64 验收完成。

macOS 管理员空间扫描只在新建的私有临时目录写入 SQLite 索引，关闭索引后才转交调用用户；客户端核验目录、文件所有者、权限及身份，再以独占创建导入自己的记录目录。`mkdtemp` 返回的指针属于输入缓冲区，必须在缓冲区指针有效期内复制为 Swift 字符串，不能在调用后的隐式指针有效期之外读取。此边界需在启用优化的构建中回归；Debug 通过不足以排除指针生命周期错误。Windows 使用独立的 C# 遍历和授权读取，不经过此 SQLite 临时目录链路。

## 授权握手回归

普通用户核实管理员辅助进程时，使用 `KERN_PROC_PID` 读取有效 UID 和微秒级进程启动时间，并核对 Unix socket 对端 PID、可执行路径及随机握手。`PROC_PIDTBSDINFO` 无法跨用户读取管理员进程，不能用于此处。只读回归核实 root 拥有的 `launchd` 以及当前进程，并保留会话复用、断线不重放、取消和范围拒绝检查。

会话建立失败显示授权未完成；只有已派发请求丢失结果通道时，才提示检查操作记录。密码界面由 macOS 提供，自动化协议检查不能代替用户在系统窗口完成认证。

两端长会话回归分别在同一认证通道完成 10,005 次请求，并检查重放拒绝、取消及断线后禁止自动重新认证。这些是本地协议／生成夹具证据，不代表原生系统认证弹窗或 Windows UAC 已完成实际验收。

应用活动回退同样通过 `KERN_PROC_PID` 读取所有者和微秒级出生身份，避免以受跨用户访问限制的 `PROC_PIDTBSDINFO` 作为管理员 worker 的回退前提。`KERN_PROCARGS2` 前后必须是相同身份；无法核实的存活进程仍阻断。活动失败诊断记录阶段、PID、原生错误和调用／目标 UID，不记录参数或环境内容。新增固定只读 `applicationActivity` 请求供授权后的组件审阅复核，不授予变更或重放旧计划。

应用选择使用同一会话：自动队列只允许首次认证，取消／失效后必须由显式行内授权恢复；授权只刷新只读证据，不自动执行。macOS worker 增加固定 `inspectApplicationShortcut`／`purgeApplicationShortcut` 能力，拒绝额外字段，限定安装根和末级失效链接的单对象清单。Windows 机器 MSI 的管理员需求由安装身份声明，行内 UAC 取消保留选择和同意；未知安装器和系统保护不提供假授权解决入口。Windows 快捷方式范围限定当前用户文件，不提升 shell 解析或执行目标。
