## 完成记录

### N01 — 记录回收与历史

默认按 7 天／256 MiB 回收派生记录，扫描时最多每小时自动维护；活跃计划、历史依赖与恢复证据受引用保护。CLI `records preview/collect`、设置入口及 macOS／Windows 分页摘要接入。3/3 专项通过；大清单依赖保护另由 N09 覆盖。初始本机六类记录有 2,992,132,938 序列化字节，仅作为开发实例基线，不代表典型用户或实际磁盘分配。

### N02 — 智能清理并发

最多四个独立位置同时扫描，根登记先于证据采集，结果保持稳定顺序和单调累计进度。7/7 并发／进度／取消／部分失败检查通过。原生生成夹具八根、1,024 文件：串行 0.151 秒，四 worker 0.060 秒；热缓存、串行先运行，不代表冷缓存或产品提速倍数。证据：`.build/next-version-native-concurrency.log`。

### N03 — 关闭应用与限定重试

身份绑定的正常退出计划有效期 120 秒，退出后重新检查应用及 helper，再刷新和重试受影响目标；保留成功结果和无关选择。1/1 专项覆盖确认摘要、身份变化、仍在运行和无文件变更。真实带未保存文档的应用退出对话框未计为已验收。

### N04 — 专属工具清理

限定 Docker 本机 default context 构建缓存、Homebrew 30 天清理策略、Conda 缓存及人工审阅的 Rust 工具链，排除当前／默认／override 工具链。项目 rust-toolchain 依赖仍需审阅。原生适配器使用固定位置与命令、有界输出／时间及独立进程组；超时记为 unknown，原计划不可重放。CLI／桌面共用计划和独立工具回执。3/3 专项包含真实生成进程的 UTF-8 输出、launcher 退出后子进程组超时回收、输出超限终止；未清理个人工具数据。

### N05 — Agent 定制闭环

`rules opportunities` 返回未覆盖目录证据与已覆盖子项标记；未知目录不会自动获得删除资格。预览在同一观测树上按文件身份去重，区分已有覆盖和新增收益。草稿禁用导入，明确启用后由桌面复用；1/1 端到端生成夹具覆盖重复收益为零和新进程持久复用。内置 Skill 更新调查、专属工具分流与收益说明；本机“通过 AI 定制”交接已检查，没有修改 Agent 全局配置。

### N06 — Windows 同步

新增 Chrome、Edge、npm、pip、Gradle、NuGet、Cargo、VS Code 八类固定缓存；项目目录发现按平台大小写去重，Chrome／Edge／Code 结合原生进程快照。WPF 标准扫描、全选、跨根单次确认、失败范围重试及共享回执已接入。Release 交叉构建 0 警告／0 错误，11 项进程 bridge 检查及路径显示检查通过；真实 Windows 原生运行独立待验。

### N07 — 独立应用残留

维护及既有历史的精确 bundle 关联，结合标准应用目录、系统注册和运行状态证明所属应用缺失；不猜名称、不删除共享容器。个人数据单独同意，执行前与逐项边界复验。2/2 生成夹具覆盖永久删除、废纸篓恢复、应用重新出现、内容变化、排除、个人数据及未知名称保留。本机只读审阅发现应用身份覆盖不完整：不能误报为无残留，也不能将所有问题归因于权限，改为中文说明并跳转覆盖范围。未注册的自定义安装仍是明确限制。

### N09 — 卡顿与大量文件性能

- 真实永久删除后台采样中，3,007 个执行样本有 1,091 个落在最终完整回执 JSON 编码；这是该次样本占比，不是全流程耗时比例。主线程多数时间等待事件。
- 超过 1,024 项的清单改为不可变 `history-manifests` 依赖，变化才写；状态转换发布小回执。先落盘依赖再发布回执，完整读取校验 ID／数量／SHA-256，旧内联记录兼容。自动回收保护依赖，明确清历史同步清依赖。2/2 专项覆盖写入失败、未知意图、损坏拒绝、回收保护及恢复。
- 逆字典序后序删除避免反复拆分路径；计量阶段减少逐文件模式处理；深度优先完成路径使用数组尾部压缩。逐文件身份及无链接检查继续保留。
- 12,000 文件、同规模生成树、交替顺序的 Release 对照：删除执行中位数 **4.101 → 2.808 秒，约减少 32%**。主回执 **3,305,065 → 1,399 字节**，另保留 **3,303,949 字节**不可变清单，不能声称总记录空间减少 99%。扫描中位数 0.583 → 0.758 秒，未证明扫描提速。该候选早于后续树遍历优化；二进制哈希及条件记录于 `.build/next-version-many-file-benchmark/result.json`。
- 真实全盘扫描另观察到汇总队列无界并发并触达 GCD 64 线程软限制。读取与汇总现共用最多八槽的调度器，子目录完成通知后才入队，父目录不占槽等待。
- 独立目录密集夹具：**18,449 条目／8,192 文件**，同一 APFS 树热扫描、交替顺序、请求八 worker，计入同样的 ps 采样开销。基线两次采样线程峰值为 **10／46**，候选为 **11／11**；扫描中位数 **1.021 → 0.992 秒**，样本不足以建立整体提速结论。每次结果容量／文件数一致，全部文件哈希不变。证据：`.build/next-version-finalizer-benchmark-isolated/result.json`。初次诊断运行与完整回归并发，未用于此结论。

### N08 — 集成、安装与实际交互

安装版已通过 158 CLI 合同、原生 bridge 的拒绝／取消／跨根单次确认／永久删除／废纸篓／恢复／历史清理，以及两个硬链接目标永久删除、所选 inode 剩余链接为零和保留文件哈希一致。最终安装清单与后续检查汇总于 `.build/next-version-verification.json`；按用户要求覆盖 `/Applications/Shou.app`，不保留旧应用。

Developer ID／公证、真实 Windows、真实专属工具数据清理、带保存提示的应用退出与所有强制中断组合仍分别待验。既有未解释夹具异常继续保留在验收文档中，新夹具不能解释旧异常。
