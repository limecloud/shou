## 3. Jev 路由对照场景

每例标注允许的路径、保留条件、可用事实、允许动作及预期模型调用。模型返回不确定时保留真实结果；测试断言路由和权限，不强迫真实模型给出特定建议。

| 场景 | 预期处理 | 关键断言 |
| --- | --- | --- |
| 仅查询占用最大的目录 | 本地排序及统计 | 两种模型调用均为零 |
| 用户明确确认生成缓存、已知模板、保留源码与配置 | 本地编译或 Jev 固定判断＋本地模板 | 主模型零调用；草稿禁用；精确范围 |
| 明确要求保留离线依赖／发布版本 | 本地明确条件或 Jev 保留 | 不被高容量／高概率覆盖，不形成该内容的清理草稿 |
| 混合目录，缺少重建证据 | Jev 选择有界取证／用户问询 | 不直接扩展删除范围；不会反复问同一题 |
| 陌生用途需要自由文本解释 | 记录原因后调用已披露主模型 | 不发送完整索引；新意图经本地校验，按需复核 |
| Jev 认证失败、畸形或超大响应 | 明确失败并保留已知结果 | 不自动调用主模型兜底，不泄露错误正文 |
| Jev 支持，但 Core 保护或匹配失败 | Core 阻断／显示具体原因 | 不以模型判断绕过规则、身份或确认 |
| 关闭时主模型调用结束、下一步准备 Jev | 本地终结／取消 | 关闭后的新请求计数为零，既有事实不伪造回滚 |

在同一案例集对照「现有主模型循环＋可选复核」与「Jev 优先」的质量、调用次数、报告 token、耗时及按实际单价计算的费用。没有价格证据时只比较用量；不能只以 Jev 单价或一次成功说明整体更省。

## 4. UI／UX 验收路径

1. 新用户：关闭 → 开启 → 无连接 → 添加／取消 → 测试失败／修复 → 保存。
2. 页面入口：智能清理空态／结果、空间工具栏／目录／树图、大文件父目录、规则页，逐一核对相同明确目标。
3. 扫描与冲突：无扫描、有效复用、部分扫描、扫描取消、已有运行任务、等待任务、取消新建面板。
4. 调查：准备、Jev 判断、本地完成、按需主模型、等待回答、继续、停止中、失败、超预算、无建议。
5. 结果：证据展开、Jev 判断、按服务用量、单条预览、零命中／受保护、保留禁用、启用新扫描。
6. 清理：现有当前范围确认、取消、明确执行、真实回执与重新测量；执行验证只用另行授权的可丢弃夹具。
7. 关闭：运行／等待／测试中的切换，离线查看、继续禁用、已启用规则仍可本地使用。
8. 辅助功能：两种语言、长路径、最低窗口、浅深色、键盘焦点、VoiceOver 实际播报及减少动态效果。

每条通过记录包路径／版本／签名、系统版本、生成数据清单、动作、观察结果及限制。不同包签名会影响钥匙串；不能用一个包的允许状态替代另一个包的读取验证。UI 操作失败、未出现预期结果或仅构建通过均不记为交互通过。
