# Windows 原生实现

[English](../../engineering/windows.md) | 简体中文

## 技术决策

Windows 使用 C#、.NET 10 LTS 和 WPF，采用 MVVM 分离视图与交互状态，使用 WPF 的 Fluent 主题。共享 Swift 核心继续负责规则、排除、扫描编排、计划、执行状态机和回执；Windows 界面通过版本化 JSON 进程协议访问随包 `shou.exe`。Win32/COM 仅放在平台适配层，不在 C# 复制规则引擎。

该路线参考知伴项目的原生界面、结构化进程桥与真实子进程测试实践。Shou 独立实现文件身份、清理确认、回收站和恢复，不继承知伴的数学阅读、WebView2、Python、网络接收或模型运行依赖。

首个验证目标是 Windows 11 x64。ARM64、旧版 Windows、网络卷、云端占位目录和跨卷操作分别验收，不能从工具链支持推断产品支持。

已审阅知伴的 `AgentProcessClient.cs`（参数数组、同时排空管道、有界严格 JSON）、`WorkspaceClient.cs`（能力发现）、`zhiban_io.c`（原生锁与持久记录）及其 Windows 验收文档。该项目同样把 macOS 交叉构建与 Windows 运行、分发验收分开记录。

## 文件系统与安全

Windows 文件证据保存卷序列号、完整 128 位 File ID 与所有者 SID，不能截断为 POSIX inode/UID。旧 macOS 记录保持可读，Windows 不使用 macOS 根目录重挂载兼容规则。记录根使用当前用户私有 ACL、稳定的跨进程锁、原子替换和持久写入。

扫描不跟随 junction、符号链接、挂载点或未知重解析点，不读取云端占位文件以触发下载。权限拒绝、预算耗尽和不完整遍历必须保留为部分结果，不能据此授权未完整测量的目标。

首版拒绝大小写敏感目录，避免将其误报为大小写不敏感。仅接受固定本地驱动器路径，拒绝 UNC/设备路径、替代数据流与保留设备名。系统目录、用户资料根、敏感目录、已配置的 OneDrive 根和 Shou 记录受保护。

普通 AppData 注册只允许资源内置的精确缓存根，变更仅限内置规则声明的缓存子树及其后代；浏览器资料、VS Code 用户数据和任意个人规则均不能扩大此授权。独立应用数据服务获得维护范围内精确个人数据根的专用权限，需另行同意。缓存根匹配与绑定复用按 Windows 大小写、分隔符等价关系处理。发现和目标公平预算复用 macOS 算法，底层由平台提供不跟随链接的读取。已匹配但未完整测量的目录可单独继续扫描，界面仅替换所选目录的证据。

Windows 内置固定位置现有 23 个，覆盖 Chrome、Chromium、Edge、Brave、Vivaldi、Firefox、Slack、Discord、Notion、Obsidian、GitHub Desktop、Insomnia、Postman、VS Code、VS Code Insiders、Cursor、npm、pip、Gradle、NuGet、Cargo、Yarn 和 uv；另有 16 条共享项目规则。这里只声明默认用户目录内的明确缓存子目录，不包含整份浏览器资料、聊天或工作区数据、编辑器用户数据、凭据、工具安装和开发环境。自定义数据位置、其他发行渠道和未声明的应用不据此视为已覆盖。应用缓存同时要求对应 Windows 可执行程序的运行证据；映射缺失或进程检查失败继续阻断清理。

四个新增位置保留了[已核查的 Windows 来源](../../engineering/windows-cache-sources.json)。Chromium 只包含 `Default`／`Profile *` 下的渲染与网络缓存目录；Obsidian、GitHub Desktop 和 Insomnia 只包含根下的 `Cache`、`Code Cache`、`GPUCache`，IndexedDB、本地／会话存储、笔记库、仓库、请求数据库、响应和插件均不获变更授权。Chrome 与 Chromium 共用 `chrome.exe`，检测到任一进程时会保守阻断两条缓存规则。Figma 暂缓：当前 Windows 指引涉及 `DesktopProfile` 并警告丢失离线改动，尚不足以确定只清缓存的安全边界。

项目清理使用标准本地 Git 安装检查跟踪状态，通过原生进程身份和已验证的工作目录检查构建活动。Git 使用有界管道、期限、Job Object 和清理后的 Git 环境变量，不从工作目录或 PATH 解析程序。进程参数不可读、仓库中缺少 Git、证据变化或不支持的进程布局继续阻断清理。这些适配仍需 Windows 原生运行验收。

原生回收站失败不得退回永久删除；恢复不得覆盖已有目标。变更前核验当前目录树和文件身份，先持久化意图，再执行操作并写回结果。未知结果保留为未知，不自动重试。Windows 原生文件竞态、回收站回执与系统行为必须独立实测。

回收站和恢复默认关闭。只有隔离原生验收进程显式设置 `SHOU_WINDOWS_EXPERIMENTAL_RECYCLE=1` 时才开启，不能作为正式用户开关。永久删除默认开放。清理页分别提供回收站与永久删除按钮；启用验收开关后，历史页提供恢复，以及单独确认后永久删除记录中的回收站项目。每次变更仍需审阅当前范围，永久删除无法恢复。

永久删除先核验完整清单，再以原生句柄固定全部已审阅对象，检查原始卷、完整 File ID、SID 和元数据，之后按子到父调用 `SetFileInformationByHandle` 删除已知条目，不递归通配删除。只有刚删除条目的直接父目录会更新本次操作造成的时间和大小变化基线，其余元数据继续核验。新子项会阻止目录删除。回收站 purge 同时固定并清除该项目对应的 `$I` 元数据记录。中途部分删除保留 unknown/pending 日志状态，阻止重试。

## 桌面进程协议

桌面桥与公开 CLI 共用核心，但不伪造终端输入，也不增加 `--yes`。桌面确认绑定本次进程中的操作、计划或回执摘要、具体选择、一次性挑战和有效期；版本、摘要或选择变化即拒绝。公开 CLI 继续要求当前范围的终端确认。

启动随包程序时使用绝对路径、参数数组、UTF-8 JSON、有界输入输出和明确错误码；stdout 仅用于协议，stderr 同时排空并限制保留量。只读请求可在取消或期限到达时终止自有进程。清理、恢复等变更请求通过协议请求协作取消，让核心在项目边界停止并保存回执；不能把超时当作没有发生变更。

请求为单行 JSON，包含 `bridge_version: 1`、唯一 `request_id`、`operation` 与对象 `input`。事件保留版本和请求 ID，以 `kind` 区分 `progress`、`confirmation`、`result`，业务内容放在 `value`。结果继续使用公开 CLI 的 `api_version: "1.0"` 信封。确认只接受当前审阅的挑战与摘要，取消和 EOF 使其失效；输入限 1 MiB，单事件限 8 MiB，客户端总输出限 64 MiB，确认有效期为 120 秒。

已连接能力与配置、工作区注册、`system.scan`/`system.clean`、`scan`/`scan.results`/`scan.target`、计划、分页历史与后续操作、个人规则预览/导入、`rules.set`/`rules.location-set`、排除，以及空间扫描/目录/分页/空间图/上下文/删除。`storage.large-files` 提供绑定查询的游标、大小/类型筛选及逐文件保护条件；WPF 大文件页复用空间删除计划、精确确认和回执。候选每页最多 100 项，大文件每页最多 500 项。删除计划最多接受 5,000 条明确路径，与 macOS 共享核心一致。该桥仍是内部传输，公开 CLI 的终端确认独立保留。

`locations.scan` 只读取自动发现的项目、额外包含目录和已存在的内置缓存位置，返回可用状态及配置版本。WPF“扫描范围”支持搜索、来源筛选、包含目录和复制路径。仅额外目录可通过 `workspace.remove` 停止包含：一次确认绑定路径与审阅版本，存储锁内再次核对版本。注销解除该目录的规则绑定、预设及工作区排除，保留文件、规则定义、其他工作区和清理历史。自动位置与内置缓存继续由发现逻辑管理。

`storage.browse` 每页最多返回 200 项及共享核心的当前保护原因，首次 `storage.scan` 也改为分页返回。名称搜索先筛选当前目录的全部直接子项再分页，通配符标点按字面匹配，续页绑定扫描、目录与查询。只读 `storage.selection` 复用 macOS 的父子去重和取消被父项覆盖的子项时保留兄弟的算法；输入及结果最多 5,000 条，展开超限整体拒绝，不返回截断选择。WPF 显示部分勾选和不重复的已选容量，导航与筛选保留选择，新扫描清空。目录加载成功后才提交前进／后退历史；面包屑、上级、分页、选择可见可操作项、复制路径、资源管理器定位及覆盖详情均已接入。仅在空间图中发现、尚未读取保护状态的节点保持不可勾选。浏览与选择不授权删除，执行仍使用新的完整清单、确认和回执。

空间与大文件页共用“扫描覆盖详情”窗口。`storage.scan`、`storage.show` 和 `storage.large-files` 返回同一保存扫描的 ID、根目录、状态、条目数、原始问题及结构化覆盖说明；筛选和翻页不改变这些信息。窗口区分读取失败、扫描期间变化、云端占位、跨卷和预算限制；部分扫描没有原因时明确保留未知状态。系统管理位置默认隐藏，可切换查看，无需调整权限。路径复制仅接受保存根内的明确相对路径，只有非系统管理的读取问题提供资源管理器定位；越界、汇总及旧版附带错误编号的诊断保留原文，不作为确切路径操作。“重新扫描此范围”固定使用窗口所示保存根，关闭和查看均不改变选择或授权清理。

`scripts/verify-storage-coverage.py` 使用生成文件验证完整扫描、真实预算截断、筛选和分页的一致性，并比较记录与文件哈希。常规宿主测试和 Windows Check 均已接入；双语言包探针新增完整、部分、有／无原因和系统位置过滤布局，报告 `storage_coverage_layout_loaded`。包探针及 Windows 原生交互仍需运行验收。

`storage.preview` 读取一个确切的已有分析项，不请求变更确认。UTF-8／UTF-16 文本最多读取开头 256 KiB，PNG／JPEG／GIF／BMP 图片最多 4 MiB，WPF 解码也限制图片尺寸。PDF、Office／ODF、RTF、常见音视频及 TIFF／WebP／HEIC 返回绑定扫描身份的 `system_preview` 描述。目录、可执行文件和其他不支持格式保留扫描快照信息。空间分析与大文件共用预览窗口，大文件另支持复制路径和资源管理器选中文件；预览内容不向 AI 调查工具开放。

WPF 通过自有 `--native-preview-worker` 进程或 COM 宿主显示 Windows 已注册的 `IPreviewHandler`。工作进程校验父进程 PID／HWND，只使用 PreviewHandlers 清单内的组件；以完整身份固定文件及祖先，只读句柄拒绝替换和并发写入。优先使用 `IInitializeWithStream`，兼容只接受路径的组件并持续保留相同句柄，不执行文件关联命令。启动限时 10 秒；成功后持续显示至关闭。关闭取消自有工作进程，组件缺失或失败时保留文件信息。实际格式支持和显示行为由已安装组件决定，当前不能视为已验证的 Quick Look 对齐。

`scripts/verify-windows-preview.py` 检查真实工作进程的输入、宿主、路径、格式和大小边界，并验证不打开记录存储。Windows Check 另构建并运行 `shou-windows-preview-checks`，只操作生成的只读流夹具，不激活已安装预览组件。双语言发行包探针检查隐藏原生预览窗口的创建和释放。Windows SDK 执行、真实组件显示、键盘焦点和屏幕阅读器均待实机验收。

清理、空间分析与大文件共用磁盘容量视图。`GetDiskFreeSpaceExW` 按实际目录读取所在卷，保留挂载点和当前用户配额语义，不将扫描占用总和当成磁盘容量。清理页显示所选工作区所在磁盘（未选择时为用户目录所在磁盘），空间分析跟随当前目录，大文件跟随最近成功应用的扫描根。页面加载、目录切换、应用重新激活及清理完成时刷新，也可手动刷新。读取在 UI 线程外执行，同一视图串行刷新并丢弃过期结果；容量未知时明确显示不可用，移入回收站不会被计为已释放空间。

`cleanup.review` 复用 macOS 的 `CleanupReview`，提供分类→规则→目录投影、重叠根去重、补扫证据替换，以及可选/推荐数量和容量汇总。搜索、分类/规则范围及仅推荐筛选每页最多返回 500 个来源，后续分页位置绑定扫描 ID、补扫映射和查询摘要。WPF 独立保存具体选择，使翻页、切换分类和搜索保留选择，并提供分组三态和全部已选容量。高风险、未完整测量及其他阻断项目不会自动推荐。投影不授予执行权限，`system.clean` 仍建立并重新核验计划，拒绝重叠选择。

候选行通过右键菜单和可用键盘访问的按钮提供资源管理器定位、路径复制、空间分析、已有 AI 审阅页与目录排除。操作使用该行确切根目录及相对路径；排除作用于来源工作区，不依赖页首所选工作区。排除后清空旧清理结果并要求重新扫描，打开 AI 页不会发起网络请求。空间页提供独立的回收站和永久删除按钮，共用回执处理，仅从视图移除成功项。回收站仍受核心能力控制且默认关闭，失败不会回退为永久删除。

Windows 默认空间测量通过原生目录游标流式写入私有 SQLite，不受删除清单条目上限截断。目录工作每次只加载有界分页，先索引直接同级目录再深入测量。完整 128 位 File ID、卷和 owner SID 在持久化后保持一致，硬链接按完整对象身份去重。读取失败、重解析点、目录变化、深度/时间预算和取消均保留明确覆盖缺口或阻止发布。大文件删除审阅使用有界内存、可取消和有期限的增量摘要，不受元数据文件 16 MiB 读取限制。这些适配仍待 Windows 原生运行验收。

## 完成页与重试同步

WPF 完成遮罩遵循共享桌面合同。成功清理只显示完成图标、回执提供的实际容量（无法测量时显示处理数量）、简短结果说明和“完成”，不会强制用户进入历史。部分完成、取消、失败或待核验时，才显示“已处理、已跳过、失败项、需核实”统计，详情默认收起，并提供“重新扫描”“查看操作记录”“关闭”。重新扫描会清空过期候选并使用当前证据重新扫描，再创建新计划；不会重放旧计划。遮罩和回执字段与 macOS 的 `CleanupResultView` 对齐，CLI 或 AI Agent 可以依据同一组状态理解两个桌面端。

历史页保留每项的身份、占用大小及恢复／永久删除资格，初始不选择任何项目，可逐项勾选、全选可操作项或清空。确认只接收明确选择的 ID，每次最多 500 项；空选择、超限或包含不支持所选操作的项目时整组拒绝。切换记录或刷新回执清空选择，加载更多历史保留当前记录。应用卸载回执的 purge 限制、未结束操作的阻断继续由共享核心负责。

`history.inspect` 接入共享的只读位置核验，只接受一个执行 ID 和可选的严格扫描预算。WPF 独立窗口显示确切原始／回收站路径、内容一致、已改变或缺失、恢复冲突、未完成的后续操作及无法核验原因，支持重新检查及关闭窗口取消自有读取。核验不会改写回执、重试变更或赋予新的操作资格。包校验覆盖有数据的历史页、选择重置和核验窗口布局，仍需 Windows 原生界面验收。清理、空间、扩展名和大文件的大小列按原始字节数排序，扩展名占比按数值比例排序。

历史页“回收扫描记录”先通过 `records.preview` 展示候选数量、记录容量估算及保留的派生记录；空结果或存在核验问题时禁用回收，默认操作为“取消”。确认后调用既有 `records.collect`，由共享核心在存储锁内重新判断资格。活跃计划、最新扫描、清理历史、恢复数据和用户文件保留。中断或断连可能已回收部分派生记录，界面提示重新检查，不自动重试。包校验接入有候选、空结果和核验受阻三种预览布局，Windows 界面验收仍待完成。

## 实现与验收顺序

### 桌面设置与界面语言

设置页提供跟随系统／简体中文／English，以及系统／浅色／深色外观和减少动态效果。外观与动态效果在保存后应用；语言变更需明确确认后重新打开应用，默认取消，并说明本次选择与未保存输入会清空。运行操作或有待处理的 AI 工作时不可重新打开。高对比度及 Windows 关闭动画的设置优先，不改动操作系统设置。

界面偏好使用 `%LOCALAPPDATA%/Shou.Desktop/preferences.json`，与引擎记录分开。文件有大小上限和版本化闭合 schema；缺失时使用默认值，无效时提示并允许通过保存替换。保存使用独占临时文件、刷盘和原子替换。设置页显示引擎 `configuration.data_directory` 返回的真实目录，尊重 `SHOU_DATA_DIR`，并提供扫描范围、规则、AI、记录回收、随包 CLI 帮助、文档、发布页、问题反馈与源码入口。复制 CLI 帮助不会启动终端或修改 PATH。Windows 更新仍需手动下载完整发行版。

`UiText` 通过内嵌的 1081 条中英文目录解析应用文案及 XAML 键，并复用共享中英文目录翻译内置引擎提示。路径、用户输入和个人规则定义保留原文。AI 认证使用与显示文案无关的固定标识；AI 调查及空间分析复制请求使用当前界面语言。`scripts/verify-windows-localization.py` 校验文案引用、XAML 键、目录完整性和格式参数，已接入常规与 Windows 检查。.NET 检查验证独占夹具中的偏好往返、错误 schema、保存失败、辅助功能优先级、目录解析、格式化及认证标识。

发行验证分别以中英文启动新的包探针，在两种窗口大小加载设置页，并应用全部外观与动态效果组合。探针不读写已保存的桌面、AI 或空间视图偏好。相关代码已在 macOS 宿主编译；本阶段尚未在 Windows 执行布局、截断、键盘、屏幕阅读器、高对比度和重新打开旅程。构建与目录检查通过不代表视觉验收完成。

### 外部 AI Skill 设置

规则页与设置页均可打开外部 AI 设置窗口。Codex／Claude Code 显示用户级 Skill 父目录，允许选择项目目录，经预览及本次确认后安装；WorkBuddy 使用原生保存面板导出 ZIP。复制请求保留随包 Skill、CLI 和所选工作区的确切路径。该流程不启动或配置客户端，不发送网络请求；导入的规则仍为停用草稿，须预览、明确启用、重新扫描，再单独确认实际清理。

`agent.setup` 与 `skills.preview` 只读且不打开清理记录存储。`skills.install` 将预览和确认绑定随包内容、客户端、目标目录、已有文件和受管版本 manifest，发布前再次复核。个人修改保持原状，受管旧版保存完整同级备份。`skills.export` 将确认绑定输出位置和归档内容，独占创建新文件。ZIP 使用确定性的 stored 条目、UTF-8 文件名和 CRC32，不调用 shell 或平台归档器。Windows 路径复用原生规范化和 reparse 检查。取消会等待请求结束；结果不明时提示检查实际目录，不自动重试。

`scripts/verify-agent-setup.py` 已接入常规测试和 Windows Check，只写生成的客户端／导出目录，验证严格输入、取消、过期审阅、个人修改、完整备份、独占输出、ZIP 内容／CRC／确定性和链接父目录（Windows 使用 junction）。发行包探针在中英文下以两种尺寸加载三个客户端选项。宿主构建与夹具通过不能证明 Windows 窗口交互、客户端发现、WorkBuddy 上传或终端 CLI 安装已验收。设置页也提供用户 CLI 命令安装，见下节；随包程序仍可通过完整路径使用。

### 用户 CLI 命令安装

**设置 → 安装 CLI 命令**先展示 `%LOCALAPPDATA%/Shou/CLI/shou.exe` 和真实随包引擎位置，再明确确认，默认取消。只安装小型原生命令及其目标文件，不修改 PATH、终端配置或系统设置；目标目录不在 PATH 时使用完整路径。请将完整应用保留在审阅的位置：命令直接启动真实 `Engine/shou.exe`，引擎更新和相邻资源保持同步。移动或删除应用后，需保留冲突内容并重新安装入口。

安装器验证有界 PE 头与一致的 x64／ARM64 架构，计算引擎及启动器摘要，拒绝链接／未下载的上级目录，发布前复核审阅状态，再独占发布新目录。相同安装不变，个人修改、未知条目和并发目标保留；写入及发布前检查取消。路径须位于本地固定磁盘。这些检查用于处理常规安装冲突，不能隔离具有同一用户文件权限的其他进程。

Win32 启动器只导入 Kernel32，安装后的入口无需附带 Swift、.NET、CRT、shell 或 Python。它读取有界 UTF-8 `shou.target`，在拒绝 reparse 后固定配置、引擎和上级目录，用文件身份拒绝递归启动自身，再直接调用实际引擎。原始参数尾部、工作目录、环境、标准流和退出码均转发。父进程的自定义控制台处理不被子进程继承，子进程保留普通 Ctrl+C 行为；交互终端取消仍待 Windows 验收。

Windows Build 通过官方 Clang 工具链直接构建启动器与独立参数／流探针，避免 SwiftPM 注入 `swiftrt.obj`；独立 C++ 夹具目标显式链接 `swiftCore` 以解析该启动对象的运行库导入。Check 通过真实安装器在独占生成目录中运行 `verify-windows-cli-install.py`，覆盖引号、空参数、Unicode／特殊字符参数、二进制 stdin、stderr、退出码、资源、junction 和内容冲突。打包拒绝启动器出现 Kernel32 之外的依赖，包含 `CLI/shou-cli-launcher.exe`；发行包探针分别以两种语言安装生成入口，再以受限 PATH 核验版本。宿主交叉编译及 .NET 检查已通过，官方 Windows 构建、上述原生夹具执行、WPF 安装及控制台旅程仍为 NOT RUN。

### 个人规则编写与版本管理

WPF 的“新建规则”依次选择确切目录或相对模式、填写大小／时间／项目标记／保留条件，再查看只读预览。声明由共享 `PersonalRuleDraft` 生成，并通过唯一的闭合规则解析器校验；Windows 大小写、分隔符与盘符的目录边界在共享路径帮助方法和原生规范化之后检查。创建不会导入或启用规则，预览不会产生可执行计划。预览展示全部匹配／保护／不满足条件的计数，最多显示前 200 行，并保留部分覆盖及问题。修改字段、停止预览、版本冲突或配置过期都会使保存依据失效。

“编辑新版本”提供完整 JSON 和共享核心建议的未使用补丁版本，支持脱离已注册工作区的规则元数据修订。校验保留原规则 ID，导入在存储锁内再次核验配置修订与版本唯一性；新版本保持停用，旧版本和已有绑定不变。选择新版本后仍须预览、启用并重新扫描。导出只写入新文件，已有文件及并发出现的目标均不会被覆盖。内置规则仍不可编辑。

桌面桥新增 `rules.draft`、`rules.validate`、`rules.revision`、`rules.draft.preview`；`rules.import` 可要求新版本并绑定审阅时的配置修订。`scripts/verify-rule-authoring.py` 在生成夹具上验证这条调用链，已加入 macOS 和 Windows Check；Windows 包校验另外加载向导三个步骤和 JSON 编辑界面的布局，不能据此替代按钮旅程或辅助功能验收。

规则页可筛选所有／内置／个人来源。“保存启用的规则”使用共享核心在存储锁内取得当前工作区实际启用的规则，并复核界面读取时的配置修订；不在 C# 重算规则集合。`presets.scan` 按保存记录的 ID 和工作区重新扫描，已停用规则会拒绝执行，不会重新启用或扩大规则范围。保存的选择只保留规则 ID，使用当前启用版本，与 macOS 合同一致。

排除支持所有工作区、当前工作区及项目，项目使用确切相对目录、模式留空保护整个项目；继承的全局排除仅展示，在所有工作区中管理。`exclusions.set` 复用共享排除校验，显式工作区／项目字段类型错误、未知范围字段或缺少项目所属工作区均拒绝，避免误写全局保护。移除按所选完整模式精确处理。变更使旧清理结果失效；包校验另外加载三个排除范围的规则页布局。

### 正常关闭应用与局部刷新

WPF 提供独立于清理的“关闭占用应用并刷新…”入口，`features.close_cleanup_owners` 仅在 Windows 开放。`cleanup.close-owners` 只接收最多 200 个不同的当前 `scan_ids`，从受阻候选和可信内置规则推导应用归属，再通过新的 `applications.close` 确认展示完整可执行路径和 PID。CLI `system close-owners --scan-id <id>` 复用相同核心服务与交互确认。任意 PID、路径或无人值守 `yes` 参数都不能扩大请求范围。

`WindowsCleanupOwnerClosing` 与 `closing.cpp` 绑定每个进程的 PID、创建时间、当前用户 SID、非零登录会话、完整可执行路径及完整文件身份。保存 intent 前复核整组目标，每个目标发送消息前再次复核其全部进程。仅向已审阅进程的可见顶层窗口发送正常 `WM_CLOSE`；拒绝提权或其他用户进程、身份变化及证据不可用的目标。保存提示、拒绝退出、后台 helper 和不可用窗口继续保留运行状态，不强制终止、不提权、不自动重放。审阅有效期为 120 秒，包含重新核验时间；持久回执不保存可执行路径。

收到回执后，WPF 在任何可取消读取前同步失效受影响的旧扫描、补扫引用及分页，仅重扫受影响工作区，保留无关证据与选择，并将路径映射到新证据中的可选来源。取消或失败保留关闭结果并说明扫描尚未完成。文件删除仍需独立的新计划与明确确认。

`scripts/verify-windows-closing.py` 检查严格输入、平台能力及 CLI 发现，不接受真实应用关闭确认。Windows Build 另外构建独立 C++ 产品 `shou-windows-closing-checks`，与受编译器崩溃影响的 Swift 专项分离。在普通用户的交互式 Windows 会话执行 `./scripts/build-windows.ps1 -NativeClosingFixtures`，只通过独占生成的 `Code.exe` 窗口验证身份过期、整组预检、取消、正常关闭与拒绝退出。管理员会话返回“未执行”，不能计为正向验收通过。包校验还检查失效状态、无关选择保留和有内容的结果布局；本阶段尚未在 Windows 执行原生夹具或 WPF 探针。

### 工具管理的存储

`NativeCleanupTools` 为 Docker、Conda 和 rustup 选择 Windows 适配，Homebrew 保持 macOS 专属。WPF“工具存储”页提供主动检查、逐项选择、影响审阅、永久清理确认、停止和回执记录。`features.tool_cleanup`、`tools.scan`、`tools.history` 及仅接受 scan／target 的 `tools.clean` 复用共享服务；Windows CLI 发现已包括 `tools scan/plan/execute/history`。所属工具成功执行后再次预览，部分完成和未知结果明确保留，估算变化不代表实际释放容量。取消或通信失败不会授权自动重放。

Windows 仅定位标准 Program Files 下的 Docker、用户目录或 ProgramData 的 miniforge3／miniconda3／anaconda3 中 `Scripts/conda.exe`，以及用户目录 `.cargo/bin/rustup.exe`，不经过 shell 或 PATH 搜索可执行文件。重解析点、占位文件、不安全的所有者／写入 ACL 及变化的文件身份均拒绝。启动和运行期间固定祖先目录与已审阅程序；受控环境不继承工具、Python 或 shell 注入变量。固定参数、继承句柄白名单、输出上限、期限及自有 Job Object 约束执行和取消。自定义安装根、Cargo／rustup home 及其他 Conda 启动器不代表已覆盖。

Docker 只接受默认本机端点 `npipe:////./pipe/docker_engine`，预览和 prune 使用确切 host，避免上下文变化将清理转向远端。仅移除未使用的构建缓存，保留镜像、容器与卷。Conda 与 rustup 沿用各自环境／工具链影响审阅。共享执行同时补齐审阅的可执行文件身份绑定、预览后过期复核，并以错误代码替代原始诊断写入回执。

两平台 runner 均固定 `RUSTUP_AUTO_INSTALL=0`，防止查询当前工具链时自动安装缺失版本。生成进程夹具检查该设置，本机验证未查询已安装工具。

默认验证不会启动已安装工具。`scripts/verify-tool-cleanup.py` 检查严格输入、历史及能力发现；Windows Build 构建独立 C++ 产品 `shou-windows-tools-checks`，`./scripts/build-windows.ps1 -NativeToolFixtures` 才会在普通用户会话额外运行独占生成的 rustup.exe，覆盖镜像变化、选项拒绝、取消、输出上限、异常退出和子进程超时。提权执行报告未运行并使正向验收失败。本阶段尚未在 Windows 执行该原生夹具或有内容的 WPF 工具布局。

### 原生验收

应用盘点由 `WindowsRegisteredApplications` 复核 `applications.cpp` 的有界源合同。四个注册表来源覆盖当前用户／全机及 32／64 位视图；普通全机安装不需要勾选系统组件或提权。当前用户 MSIX 包使用公开 WinRT `PackageManager`，不读取内部 AppModel 注册表。相同注册项及相同证据的视图别名去重，同名但不同注册身份保留。注册表父源和逐项元数据读取前后复核，变化时保留覆盖问题。条目、时间、输出及问题数量均有上限，停止支持协作取消；桌面请求按只读进程处理。

`applications.scan` 和 Windows CLI `applications list` 在打开清理存储之前读取，不注册工作区，不扫描安装内容，不输出卸载命令。登记的安装位置仅展示，不作为归属证据。`EstimatedSize` 明确为安装程序报告的大小；盘点不测量 MSIX 安装内容，也不确认可卸载状态，独立按需目录测量见下节。框架／资源／bundle 组件默认隐藏，系统包可移除性仍交给 Windows 判断。WPF 提供搜索、来源筛选、列排序、详情、覆盖及固定 Windows“已安装的应用”入口。`application_inventory`、`application_usage`、`application_uninstall` 与完整 `applications` 能力分开；应用数据归属及独立残留尚未完成，后者继续为 false。

`scripts/verify-windows-applications.py` 已加入 Windows Check，原生分支只读取当前注册表／包源、检查条目预算和 CLI，不创建虚假注册项、不执行卸载、不接受变更确认。macOS 只执行输入拒绝和平台边界检查。包校验新增应用页布局及 `application_inventory_layout_loaded` 断言；这些检查源码尚不代表 Windows 已运行验收。

### 安装目录占用

选择一个应用行，点击“测量安装占用”，即可按需测量当前登记的安装目录。独立列同时保留安装器登记大小和实测占用，按原始字节排序；可展开详情随当前行切换，展示应用名、确切目录、逻辑大小、去重文件数及不完整覆盖。重新测量先清除该行旧值，取消或失败保留明确状态；重新盘点会清空这些观察结果。部分数值只描述遍历时已观察到的条目，不能保证是正在变化目录的当前容量下限。

独立 `application_usage` 能力与只读 `applications.usage` 桥操作只接受当前已存储的 `scan_id`、一个 `application_id` 和可选条目／时间预算。Windows CLI 提供 `applications usage scan/measure`，默认 100,000 项和 30 秒，上限 1,000,000 项和 120 秒。服务要求原登记来源完整，并在测量前后复核登记未变。原生适配按确切注册表来源／视图读取桌面或 MSI 的 `InstallLocation`，MSIX 使用 PackageManager 的 `InstalledLocation`；只测量本地固定磁盘目录，缺失或不可访问的位置保持不可用。

目录游标固定祖先身份，拒绝 reparse／在线占位条目；按卷与文件身份去重，区分逻辑大小和实际分配，保留条目／深度／时间／读取／变化问题。只读取文件系统元数据，不读内容、不改应用文件、不创建删除计划。目录可能包含共享文件，也不包含全部关联数据；不同应用可能指向重叠目录，不可直接相加，也不据此声明可释放容量或数据归属。

`scripts/verify-windows-application-usage.py` 执行拒绝／平台检查，不发起有效安装目录扫描。Windows Check 另外运行六项原生输入／启动前取消门禁。`./scripts/build-windows.ps1 -NativeUsageFixtures` 使用生成的本地文件与进程内注册表重定向，检查硬链接计量、有界部分遍历、登记变化及文件保留；不测量已安装应用或 MSIX。包探针在两种尺寸加载生成的实测／部分行，验证旧扫描不能测量，并报告 `application_usage_layout_loaded`。Windows 原生执行、真实 MSIX／登记位置、ACL／reparse／句柄集成及 WPF 旅程仍待验收。

### 通过登记的安装器卸载

WPF 默认不选择应用，最多明确选择 20 个注册项；一次确认展示名称、版本、登记发布者、卸载程序及注册标识，默认按钮为“取消”，另需勾选理解可能删除应用数据且无法通过 Shou 恢复。桌面 `applications.prepare-scan` 保存有界扫描，`applications.uninstall` 只接受其 `scan_id` 和不同的 `application_ids`，拒绝任意路径、可执行参数及无人值守 `yes`；`applications.uninstall-history` 读取独立回执。Windows CLI 提供 `applications installer scan/plan/show/execute/history`，执行必须在终端输入当前 `UNINSTALL WINDOWS <plan-id>`。

共享服务在第一个安装器启动前复核整组，检查扫描／计划期限，单次消费确认，并在每次启动前持久化意图。桌面安装器只使用登记的绝对 EXE，不经过 shell 或 PATH；固定完整文件身份，拒绝不安全 ACL、重解析点、相对命令和 Windows 系统辅助程序。MSI 固定使用系统 `msiexec.exe /x {product-code} /norestart`，并由 Windows Installer 独立核对已安装产品名称、版本、发布者及用户／全机范围。当前用户 MSIX 使用公开 `PackageManager.RemovePackageAsync`；不支持的登记方式仍可通过 Windows 设置管理。

应用保持 `asInvoker`，安装器确需提权时交由 Windows 展示本次 UAC。停止或超时只结束等待，不终止安装器，也不取消已经请求的包移除。结果不明时不启动后续安装器，须先核实 Windows 实际状态再重新扫描。不能仅凭退出码 0 判断完成：必须重新完整读取原注册来源，确认原注册项及对应 MSIX 包系列已缺席。登记大小不作为已释放磁盘容量。此流程不证明数据归属，也不独立清理残留；所属安装器可能删除用户数据。

默认 Check 仅检查安全输入和能力发现；Build 另构建 `shou-windows-uninstall-checks`。普通用户 Windows 会话可显式执行 `./scripts/build-windows.ps1 -NativeUninstallFixtures`，只运行生成的私有 EXE／注册夹具。注册表重定向仅影响夹具进程，不运行已安装卸载器、不调用 MSI 卸载或 MSIX 变更；覆盖注册／操作／镜像变化、启动前取消、异常退出及超时后生成安装器继续运行。管理员会话报告未运行并使正向验收失败。Windows SDK、UAC、真实 MSI／MSIX 及 WPF 按钮／辅助功能仍待验收，布局加载不能替代这些结果。

### 应用数据与维护范围内的残留

应用页可单独审阅 Chrome、Chromium、Edge、Brave、Vivaldi、Firefox、VS Code／Insiders、Slack、Discord、Notion、Obsidian、GitHub Desktop、Insomnia、Postman、Cursor 的个人数据。16 类维护关联覆盖 17 个精确默认数据根，Firefox 同时包含 Local 和 Roaming。安装目录及混合发布者父目录不在其中。所有组件均视为个人数据，可能包含设置、登录状态、资料和本地数据库。此目录流程不处理 MSIX 数据，已登记 MSIX 使用下述独立操作。自定义／便携安装、其他账户和未声明应用尚未覆盖；声明登记来源缺席不能证明便携安装不存在。

`applications.data-scan` 只接受可选布尔值 `leftovers_only`，默认 true；false 同时审阅已登记应用。四个注册表来源和当前用户 MSIX 来源必须完整读取或确认不存在，才能审阅数据。应用运行或无法核验、链接、共享文件、身份变化、扫描不完整及配置排除均阻断清理。完整清单保存在私有审阅记录中，桌面桥只返回有界摘要；普通缓存与空间引擎没有个人数据授权。

WPF 窗口默认不选择、不同意个人数据清理，每次扫描撤回同意，展示路径、实测估计及保护原因。先单独同意个人数据，再逐项选择；`applications.data-clean` 仅接收 `review_id`、1–32 个 `component_ids` 和 `include_user_data=true`，随后另行确认永久清理。审阅有效 900 秒，计划有效 120 秒；整组及每项执行前复核登记、活动、父目录身份、完整清单、排除、配置和期限。删除复用原生清单边界、持久化意图和共享历史，无法恢复、不自动重试。停止或关闭等待协作结果，窗口关闭后刷新主页面历史。

Windows CLI 提供 `applications data scan/plan/show/execute`；计划需 `--include-user-data true`，执行需在终端输入 `PURGE <plan-id>`。独立 `application_data` 能力不代表完整 `applications` 对齐。派生记录维护已包含这些审阅和计划，保护有效／执行中计划，并保留历史清单依赖。

`scripts/verify-windows-app-data.py` 已接入常规测试和 Windows Check，只验证发现、非法输入、同意拒绝及证据缺失，不发起有效原生数据扫描或清理。Core 生成夹具模拟 Windows 身份／登记事实，仅操作隔离主机文件。包探针在两种尺寸检查同意／选择布局并报告 `application_data_layout_loaded`，不扫描用户数据。Windows SDK、真实 AppData ACL／junction／句柄、登记／活动集成和 WPF 键盘／辅助功能旅程，本阶段均为 NOT RUN。

### 已登记 MSIX 应用数据

应用页提供独立“清空所选 MSIX 数据…”操作，只接受明确选择的 1–20 个当前用户包。要求当前完整登记扫描、对应包家族进程已停止、登记元数据未变，以及已存在且属于当前用户的数据目录身份。框架／资源／bundle、系统内置／来源不明及 Shou 自身包受保护。不支持或无法核验的包仍可在 Windows 设置中管理；未登记 MSIX 残留和其他账户数据不在此范围。

原生适配使用公开的 `ApplicationDataManager.CreateForPackageFamily` 和 `ApplicationData.ClearAllAsync`，由 Windows 清空整包的本地、漫游、临时数据和设置，保留安装。这是整包操作，文件清理排除规则不限制其范围，需要保留任何内容时应取消。确认默认取消，另需勾选个人数据同意；无法恢复，也不据此报告释放容量。普通文件清理没有获得 `Packages` 目录权限。只读审阅不打开或初始化应用数据存储；执行将首次访问存储视为可能发生变更。

独立 `application_package_data` 能力及桥操作 `applications.package-data-clear`、`applications.package-data-history` 只使用已存储的登记 ID，不接受路径或执行参数。Windows CLI 提供 `applications package-data scan/plan/show/execute/history`，需 `--include-user-data true` 和终端口令 `CLEAR MSIX <plan-id>`。计划有效 120 秒，整批与逐项复核，任何可能的 Windows 变更前先保存意图。取消或超时只结束等待，不取消 Windows 操作；结果不明时停止后续项并消费确认。独立回执持续保留，派生维护保留执行中计划和全部包数据回执。

`scripts/verify-windows-package-data.py` 检查拒绝、独立同意、证据缺失、发现及空历史，不发起有效原生数据扫描或清理。Windows Build 构建 `shou-windows-package-data-checks`，常规 Check 执行七项输入／启动前取消检查，均不调用包 API。包探针用生成的 MSIX、混合及过期选择检查门禁，在两种尺寸加载回执并报告 `package_data_layout_loaded`；发行验证也核对随包能力。这些检查不代表 Windows 包 API 正向验收。macOS 宿主上的 Windows SDK 构建、真实包／进程／ACL、确认键盘／辅助功能旅程和双语言包探针仍为 NOT RUN。

### 剩余原生验收

1. 完成 Windows 构建、完整文件身份、私有记录存储和核心合同兼容。
2. 连接 WPF 界面，完成目录选择、规则、扫描、候选审阅和计划。
3. 用生成夹具验证明确确认、回收站、永久删除、历史、恢复、取消及故障回执。
4. 完成空间分析、大文件与排除交互，未接入能力按实际发现禁用。
5. 在 Windows 执行原生系统与界面验收，再验证签名、升级和干净系统安装。

`scripts/build-windows.ps1` 构建生产核心和 WPF，执行进程测试及原生永久删除协议夹具。当前 Swift 6.2.3 Windows 编译器在 `shou-windows-tests` 出现 SIL 崩溃，脚本暂时跳过该 target，不能将 ACL/junction/锁/回收站/安全证据专项计为已执行。`scripts/package-windows.ps1` 发布自包含 .NET，从显式指定的官方运行库目录复制 PE 依赖闭包与 SwiftPM 资源，记录 SHA-256，并在受限运行库搜索路径下执行能力发现。Windows 11 提供 `winsqlite3.dll`。构建细节见 [Windows 说明](../../../apps/windows/README.md)。

启动项新增 `startup.scan`／`startup.control` 桥和 WPF 页面，复用共享来源覆盖与状态模型；读取不依赖清理存储，配置摘要与单次确认绑定当前选择和操作。原生控制只使用 Task Scheduler 公开接口，不操作 StartupApproved 或整个系统权限。来源、未知状态、快捷方式解析和直接控制边界见[启动项产品合同](../product/startup-items.md)。Windows Check 阶段执行 `verify-windows-startup.py`：只读盘点、伪造／过期选择拒绝及取消确认；脚本固定不接受任何变更确认。

Windows CLI 帮助和定向 capabilities 已展示实现的 `startup list`、`startup control`、隐私、工具、`applications installer` 和 `applications data` 命令。尚未支持的通用应用变更继续隐藏。Windows 启动项验证脚本先检查其帮助与能力发现合同，再读取原生来源。

浏览器隐私复用共享扫描、计划、明确确认和逐来源事务流程。WPF 默认不选来源，Cookie 需单独同意退出登录；永久删除不进入回收站且无法恢复。仅支持标准 Chrome、Chromium、Edge、Brave 与 Firefox 配置，不接受自选配置根。Windows 原生访问固定数据库及祖先目录，拒绝重解析点、硬链接和不安全写入 ACL，重新核验所有者、浏览器活动、格式及计数；只返回汇总数量和脱敏回执。生成夹具覆盖时间范围、取消与过期扫描拒绝，发布前仍需 Windows 工作流通过原生 ACL 和事务分支。

普通用户运行不应依赖开发工具链。开发目录、交叉编译成功、macOS 桥测试和 Windows CI 配置不能代替干净系统安装证据；运行库再分发许可、签名、安装器、升级与卸载仍需验收。

Windows GitHub 工作流分别检查静态资源、Swift/WPF 原生构建和生成夹具及真实进程合同。`scripts/build-windows.ps1 -Stage Build` 与 `-Stage Check` 对应构建和验证，省略 `-Stage` 时两者都会执行。.NET SDK 以 `apps/windows/global.json` 为准，Swift 与 Python 版本在工作流中声明。任一检查失败都不会上传开发产物，同一引用的新运行会取消旧运行。
