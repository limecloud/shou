## 诊断日志

GUI 与 CLI 共用 `%LOCALAPPDATA%\Shou\Diagnostics\application.jsonl`，最多保留当前与上一份各 1 MiB。每行是版本化 JSON，包含时间、应用／系统版本、架构、进程与会话、操作编号、父操作、阶段、耗时、状态、数量、错误码、HRESULT、内部异常的 Win32 数字码与方法调用栈。页面状态层消费的异常也记录；部分覆盖、取消、失败和未完成分别呈现。CLI `request_id` 的 `request_` 后缀对应根操作编号；智能清理失败界面显示诊断编号。

默认不记录原始路径、SID、异常消息、命令参数、文件内容、浏览记录或凭据。路径使用每进程随机密钥的 HMAC 引用，只能在同一进程内关联。`SHOU_XAML_STARTUP_DIAGNOSTICS=1` 只额外记录有界 XAML 解析消息，属于显式本机排错选项；CI 环境本身不自动开启。

日志目录和文件使用当前用户所有者及私有 ACL；打开时核验句柄、类型和单链接，不跟随 reparse point。普通诊断失败不能改变业务操作结果，丢失计数写入后续事件；E2E 将日志缺失或丢失计数视为失败。永久变更的持久化意图日志仍是独立安全边界，写入失败继续阻止变更，不能被普通诊断的尽力写入语义替代。

系统预配账户的 LocalAppData／既有 Shou 容器可能归 SYSTEM 或 Administrators 所有。默认路径只接受经固定句柄核验、无其他主体写权限的上级目录，不修改现有权限或所有者。Data／Diagnostics 叶目录和文件仍要求当前用户所有及私有 ACL。`SHOU_DATA_DIR`／`SHOU_DIAGNOSTICS_DIR` 显式覆盖使用严格的当前用户父目录约束。缓存与扫描根的所有者检查没有因此放宽；不可验证的位置仍报告覆盖缺口。

macOS 本机运行 `sh scripts/test-windows-core.sh`。`WindowsFact` 与管理员专用生成夹具在不满足宿主条件时明确跳过；跳过不能记作通过，不为产品扫描提权。Windows 使用 `scripts/windows/test.ps1`，无论通过或失败都归档 TRX 和可获得的诊断清单。CI 另保存发布诊断。

Windows 流水线另在标准 `windows-11-arm` runner 上执行原生 ARM64 主套件，并读取同一流水线的 ARM64 交叉构建归档。运行前核对归档及逐文件摘要、确切源码／版本／关闭门禁、宿主／PowerShell／.NET 的原生架构、apphost／CLR／WinUI 的 PE 架构，以及 CLI 诊断报告的实际进程架构。发布检查保存窗口启动与正常关闭回执；实际通过、失败和跳过以 [SYNC.md](../../../SYNC.md) 为准。该任务不启动付费云电脑，也不提供普通用户完整界面、签名安装或更新验收。

`pwsh -NoProfile -File scripts/windows/test-e2e-harness.ps1` 在隔离的生成日志中验证 E2E 自身的拒绝关联与证据检查；Windows 主测试脚本也运行它。它不启动应用、不执行系统变更，不能计为真实桌面 E2E。

## 真实桌面 E2E

在已登录、解锁的 Windows 当前用户会话运行。脚本拒绝 Session 0 和非 STA 环境，不修改系统权限，不接受现有软件作为变更目标：

```powershell
powershell.exe -NoProfile -STA -File scripts/windows/test-desktop-e2e.ps1 `
  -PublishRoot "C:\ShouBuild\win-x64\publish" `
  -ArtifactsRoot "C:\ShouBuild\e2e"
```

每次生成独立的私有记录目录和项目夹具，不覆盖用户已有 Shou 配置。失败控件树记录应用／根控件／子控件的进程 ID、原生句柄、类名、框架与支持的自动化模式，以区分原生选择器宿主及权限差异；读取失败单独落盘，不静默忽略。UI 自动化只查找本次进程及稳定控件 ID。超时、页面失败、意外退出、缺少控件或日志、数据变化和无法正常关闭均失败；失败保留窗口截图、该进程的控件树、JSON 日志及逐步结果。原生目录选择器不能定位时也失败，不能改成直接注入页面结果。每步开始与结束原子写入 `checkpoint.json`，包含当前步骤及已完成／失败结果，且明确 `verification_complete=false`；最终 `verification.json` 才是完整回执。预算截止时先导出 checkpoint，不能为等待收集器持续开机。

每次选择生成目录前正常关闭并重新启动应用，避免已缓存的结果页隐藏起始页按钮而阻断后续旅程。清理成功页另存返回前截图。无交互确认与重放拒绝只有在退出码、错误码、CLI `request_id` 和日志父操作编号精确一致时才算预期行为；每次要求唯一匹配日志并另行保存。其他请求、界面失败或未支持能力没有全局豁免，仍阻断日志健康检查。

| 旅程 | 当前 E2E 断言 |
| --- | --- |
| 首次智能清理 | 实际点击开始；等待位置准备完成；接受有依据的空／完整／部分状态，拒绝准备错误 |
| 生成清理项目 | CLI 登记、导入并启用个人规则，扫描结果、精确单项计划，确认永久删除，核验目标消失／保留字节／历史记录并拒绝重放 |
| 智能清理结果 | WinUI 找到生成 target；展开分组；无匹配搜索清空结果，再恢复；通过选择菜单清空，再直接从清理主按钮准备并确认计划；新增独立完成页、隐藏旧列表／原始详情及返回断言，尚未原生复验 |
| 空间分析 | 原生选择器选择生成项目；实际启动／停止和完成扫描、目录树；生成文件删除取消／确认及保留字节检查；本轮被选择器阻断 |
| 大文件 | 原生选择器选择生成项目，扫描完成、文件列表及生成文件确认删除；本轮尚未执行到 |
| 应用／启动项 | 真实注册来源加载为完整或部分；无匹配搜索产生空列表；不卸载或控制真实项目 |
| 规则／历史 | 规则筛选；只读操作没有产生执行历史 |
| 隐私 | 仅新建随机 Chromium profile 和生成 Cookie 数据库；检查 Cookie 预审阅门禁、选择统计／清空／撤销、独立的本次永久删除与退出登录同意、取消后数据库摘要不变、确认删除及单独完成回执，SQL 复核旧记录与无关表保留，并在正常重启后从隐私历史读取回执；本轮尚未执行到 |
| 设置 | 减少动效写入私有记录，正常关闭、重启后状态保持；扫描位置及排除项进入真实编辑界面，新增断言尚未原生执行 |
| 故障／恢复 | 用生成普通文件占据数据目录位置；UI 失败有结构化异常；文件字节不变；恢复正常数据根后可加载 |
| 完整性／日志 | 生成项目所有文件哈希保持；没有意外失败或丢失诊断；记录精确产物摘要 |

这些源码用例须在真实 Windows 执行并审核回执后才算通过。生成清理流程只操作本轮临时目标；MSI 卸载与计划任务控制仍使用 [Windows 开发](windows.md)中的独立显式 opt-in 入口；上述空间／大文件／隐私源码用例未运行即不通过；应用卸载／启动开关的真实界面变更仍未覆盖，真实界面执行中断、语言切换、全部筛选／分页、键盘／屏幕阅读器、DPI／明暗／高对比、ARM64、签名／安装／更新及 Mac 逐页 1:1 对比仍须独立取证，不能从本脚本推断通过。

## 证据导出

```powershell
./scripts/windows/collect-diagnostics.ps1 -OutputRoot "C:\ShouBuild\evidence" `
  -TestResultsRoot "C:\ShouBuild\tests\results" `
  -PublishRoot "C:\ShouBuild\win-x64\publish"
```

清单保留 TRX 汇总计数和逐个 `UnitTestResult.outcome` 的 `result_counts`；xUnit 可能出现汇总 `notExecuted=0` 而实际结果为 `NotExecuted`，必须列出跳过。另包含日志、架构、空间、缺失项和产物 SHA256；通过 XML 属性读取带命名空间的 TRX，避免空计数被当成测试通过。E2E 另生成 `verification.json`、逐步截图和命令输出。原始截图及控件树可能包含当前用户可见的应用名称／路径，仅保存在私有证据目录，分享前复核。导出成功本身不构成验收通过。云端导出完成后按最新生命周期选择关机保留或释放。
