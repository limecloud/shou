# 能力职责与交付规划

[English](../../engineering/capability-plan.md) | 简体中文

## 产品边界

| 能力 | 领域职责 | 系统职责 | 验收要求 |
| --- | --- | --- | --- |
| 空间分析 | 计量、分页、覆盖状态、精确选择 | 枚举、身份和分配容量 | 准确表达部分结果，分页稳定，取消有界 |
| 日常清理 | 规则、排除、所有权门槛和计划 | 访问、应用活跃状态与原生变更 | 仅使用当前完整目标，逐项持久化结果 |
| 个人规则 | 闭合 Schema、禁用导入、预览和启用 | 明确范围访问 | 不扩大范围，不绕过保护数据 |
| 工具清理 | 固定类型操作与影响披露 | 固定本地程序、上下文和有界输出 | 不执行任意命令或远程上下文 |
| 应用 | 精确所有权、独立个人数据同意 | Bundle 或安装器、注册表语义 | 未知所有者保持未知，平台范围明确 |
| 启动项 | 注册状态和受支持控制审查 | 系统注册、查询与控制 API | 不推测运行、启用状态，不做未支持变更 |
| 隐私 | 明确来源、时间范围与退出登录同意 | 配置访问、数据库锁和 Schema | 仅处理限定记录，不删除整个用户配置 |
| AI 调查 | 证据预算、问答、路由与禁用草稿 | 凭据与模型通信 | 离线清理可用，模型没有变更授权 |
| 历史 | 持久化意图、逐项结果与引用保护 | 私有存储、原子写入和锁 | 核实中断任务，恢复不覆盖文件 |

## 交付规则

一次实现从原生入口、领域、平台到记录结果的完整小链路。领域测试与原生测试提供不同证据。具备领域和平台行为后再增加页面，用户可见能力以实际验证为准。

macOS 使用 Swift 服务，Windows 按[实施方案](windows-native-plan.md)使用独立 C# 服务。通过共享合同和生成资源对齐行为，在 [SYNC.md](../../../SYNC.md)跟踪每项安全变化与刻意差异。

## 优先级

扩展覆盖范围前，优先保证扫描正确、有界工作、精确确认、持久化结果和恢复。记录保留保护活跃计划和恢复证据。性能变更必须验证完整结果一致性与取消。分发必须在每个支持架构上获得干净安装和更新证据。
