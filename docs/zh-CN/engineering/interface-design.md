# 原生界面设计

[English](../../engineering/interface-design.md) | 简体中文

## 信息层级

围绕用户任务组织界面：扫描、检查、选择、清理。导航、页标题和主要动作位置稳定。精确路径、风险、覆盖缺口与重建后果靠近受影响的选择项。普通用户流程不展示内部模块名和计划实现细节。

主要入口包括智能清理、大文件、空间分析、规则、启动项、应用、隐私、历史和设置。Windows 原生预览采用 216 点侧栏，按存储与工具分组，历史和设置置底；页标题与工具栏由窗口统一承载，正文按起始、扫描、结果和失败状态组织。应用与启动项使用紧凑列表和按需详情，规则支持完整目录浏览、来源过滤、搜索与具体位置的开关；空间分析使用目录树、扩展名统计和矩形面积图。入口可见不代表对应变更能力已开放。

## 选择与结果

列表、空间图和分类视图使用同一份选择状态。父子项去重，统一展示分配容量估算。路径保留开头和文件名，中间只出现一次省略，悬停与辅助功能提供完整值。

桌面默认永久清理，执行前确认当前精确选择、不可逆后果及独立同意的个人数据。可选废纸篓或回收站使用明确动作名称。结果区分完成、跳过、失败、取消和未知；移入废纸篓不描述为已经释放磁盘空间。

Windows 智能清理源码使用独立完成页，不把已失效的扫描列表当作执行结果。成功页只显示回执时间、已完成目标的容量估算与不可逆提示；异常页提供已移除、跳过、失败和待核实计数，详情按需展开，并可重新扫描、查看历史或返回。缺少或不匹配回执时，不推断文件未变化。清理主按钮先准备当前精确计划，再交给现有的本次确认流程；选择菜单本身不生成计划或执行清理。界面项目数按规则组统计，计划仍保留每个位置与目标。历史每次进入均刷新记录。新增完成页与交互断言尚须在 Windows 实机复验。

## 原生行为

macOS 使用 SwiftUI/AppKit，Windows 使用 WinUI 3。共享颜色、字号、间距、圆角与文案通过资源生成，同时遵循平台键盘、焦点、对话框、窗口和可访问性习惯。验证明暗、高对比度、减少动效、长翻译和 DPI 缩放。页面状态可在本平台内独立测试，UI 框架类型只留在应用层。

## 共享设计资源

已提取的设计值只修改 `assets/design/tokens.json`。运行 `python3 "scripts/generate-windows-resources.py"` 生成，再加 `--check` 校验可重复性。同一命令输出 `apps/windows/Generated/Design.xaml` 和 `apps/macos/Sources/ShouDesign.generated.swift`，均不手工修改。清单记录规范来源与生成器摘要，Swift 文件头记录来源摘要。

Schema 版本 1 支持命名 sRGB 颜色（`#AARRGGBB`）、数值、统一圆角，以及数值或四边数组 `[左, 上, 右, 下]` 表示的内外边距。四边数组仅允许出现在 `thicknesses`，生成 Windows `Thickness` 和 SwiftUI `EdgeInsets`，保留边序；统一数值继续生成 `CGFloat`。名称以 `Shou` 加大写字母开头，仅包含 ASCII 字母／数字，在各组间唯一。数值须有限、非负且不超过 4096；拒绝布尔值、字符串、重复 JSON key 与未知分组。Swift 颜色保留四个通道，数值使用 `CGFloat`。设计资源不进入 Core 或 CLI 依赖。

当前提取值包含主操作与清理动效尺寸、路径宽度、动效周期、侧栏／标题栏／列表尺寸、正文字号、起始页字号、大文件标题字号和摘要数字字号。SwiftUI 使用强调色、设置间距／卡片圆角、扫描位置面板内边距与清理动效值；WinUI 接入共享强调色、间距、圆角、字号、页面尺寸、侧栏胶囊色与系统链接色。窗口前台时侧栏列表选中为系统蓝胶囊，文字和图标为浅色；未选中图标为次要色。历史和设置选中为强调色淡底。磁盘用量条使用次要色。高对比度仍用系统高亮。macOS 扫描与清理共用平面文件聚拢动效；Windows 使用原生活动圆环，减少动效或系统禁用动画时改用静态指示。Windows 设置按用户持久化语言、明暗主题及减少动效；语言变更重建窗口，外观即时应用。v0.13.0 基线公开变更门禁关闭；未发布 v0.14.0 工作区已组装受原生平台约束的入口，但完整执行和视觉验收未完成。Windows 精确图形、多层面积图、全部 DPI 与可访问性验收仍须单独完成；编译和资源检查不能代替布局与交互证据。

## 验证

使用生成数据检查空、加载、部分、就绪、确认、执行、停止中、失败与完成状态。检查返回来源页、重新扫描、选择保持、确认取消和辅助标签。真实 UI 证据与状态测试分别记录。见[流程](../architecture/workflows-and-sequences.md)和[验收](acceptance-and-testing.md)。

页面主体沿用 Mac 的信息布局：智能清理结果用分类摘要、规则组和按当前选择更新的清理底栏；应用和启动项用摘要数字、诚实筛选胶囊、搜索和行内详情；历史用独立卡片和详情入口，不补造目标名或字节；规则用横幅、扫描位置旁的版本选择、来源分段，以及摘要、限制和位置；空间分析用强调色面包屑、简洁／详细切换，简洁视图把面积图放到剩余高度；隐私空状态把说明和时间范围放在上方、扫描放在工具栏；设置用分组卡片，并显示本机数据目录与支持链接。52 点标题栏、28 点导航行、34 点状态栏。窗口处于前台时侧栏列表选中为系统蓝胶囊。空间图按目录递归嵌套并使用扩展名色板。Windows 的注册容量、未知启动状态、预览门禁与未实现 AI／更新保持准确，不冒充 Mac 能力。清理、卸载和启动开关底栏按钮按当前平台、选择与审阅状态决定资格，不能用固定禁用替代真实闭环；当前未发布工作区仍须补齐验收。以上为源码布局，最终 1:1 结论须以本轮 Windows 原始截图、相同状态与 DPI 对比为准。

应用与启动项的摘要、筛选和列表处于同一张 10 点圆角卡片内；摘要数字 15 点、名称及摘要正文 12 点、图标占位 32 点，来自 Mac 视图源码与本机字体实测。部分覆盖以摘要链接进入详细说明，不重复占据主列表上方一整行警告。正常就绪时不重复显示状态数量；错误、停止与取消仍单独可见。无需分页时隐藏分页操作；应用默认按已登记容量降序显示，未知容量置后，用户仍可显式按名称排序。以上改动尚待 Windows 原生截图及交互复验，不代表逐页 1:1 已验收。

应用底栏的选中计数随选择变化更新，不等待列表重新加载；只读选择的 E2E 反馈断言仍须原生执行。

隐私结果使用选择框、28 点图标占位、浏览器／配置与类型、独立记录数、140 点状态列及 14 点行内边距；横向底栏显示选择统计、清空与审阅，回执单独成卡。设置页使用 20 点页面内边距、24 点组间距、8 点组内间距、19 点图标／26 点占位、11 点副标题、水平 18／垂直 17 点行内边距及 58 点缩进分隔线，两端共用这些设计值。Windows 设置的扫描位置及排除项按钮进入现有规则编辑界面；AI、更新等未实现能力保持明确禁用。隐私历史使用独立折叠区显示只读回执；同状态 Windows 截图和新增真实控件 E2E 仍未验收，不能据此声明逐页 1:1 完成。
