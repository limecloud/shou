## Native workflow

Add a connection in Settings → AI Investigation. Protocol, API base URL, model and authentication are independent. Responses, Chat Completions and Anthropic Messages support compatible gateways. Include the gateway prefix but omit the protocol endpoint suffix. Remote endpoints require HTTPS; HTTP is restricted to loopback.

macOS defaults to `local` authentication: private per-user credential files, with references in connection profiles. Windows defaults to Credential Manager (`keychain`) and also supports `local`. Explicit environment variables and unauthenticated local services are supported; SDK provider environment defaults are never used. Connection tests send a generated token and require tool execution followed by another model turn.

Connections enable Structured Decisions and select Jev, the only bundled provider, with an independent TypeSafe root/model/authentication; the main model is required. Disabling Jev retains decision settings and credentials and routes new tasks directly to the main model. Local storage goals run first, then bounded classification/questions/rebuild review and local rule templates. Open-ended understanding records a reason before main-model escalation; technical decision failures never trigger paid fallback. A fixed `POST /systemone` Choice question receives proposed relative metadata, model hypotheses, rebuild conditions and explicit user answers. Only `supported` can produce a disabled draft; `needs_information` requests more evidence and `retain` keeps content. Invalid or failed decision responses fail the investigation rather than being hidden by SDK tool-error handling. Reviews appear separately in the inspector; confidence does not authorize deletion.

After scanning, choose Investigate to open a resizable native inspector. It shows the fixed investigation folder, destination and disclosure before the user starts. Browsing does not change an active scope. Changed scans and cleanup invalidate suggestion preview. Questions pause the investigation; answers resume it. Each suggestion opens its own existing rule preview, importing a disabled high-risk draft. Enabling, rescanning and confirmed cleanup remain separate user choices. No investigation tool can delete.

## Shared implementation

| Layer | Responsibility |
| --- | --- |
| ShouCore | Connection/task/question/advice DTOs, evidence scope policy, closed rule parser and disabled import |
| ShouPlatform | Local records, private credential files, legacy macOS Keychain, Windows Credential Manager, explicit environment credentials |
| ShouAI | macOS SDK `0.20.0`, bounded Windows protocol runtime; shared routing, index tools, budgets and checkpoints |
| macOS | Native Form/SecureField connection editor, inspector, cancellation and independent rule previews |
| CLI/desktop bridge | The same investigation service, progress events and SDK/URLSession cancellation |

The SDK is pinned to `4e0230a06092583c4dd541071b1ce8e181821bf9`; its Apache-2.0 license ships in the app. SDK types/messages stay inside ShouAI and never enter cleanup rules, plans or execution. The SDK owns the macOS tool loop. Windows uses a bounded runtime adapter for the same evidence tools without importing Apple-only SDK APIs or duplicating the rule engine.

Evidence consists only of saved index metadata: relative paths, kinds, allocated bytes, counts, newest modification and coverage. Pages contain at most 30 rows, with 300 rows/64 KiB per investigation. Credential locations, links and special files are filtered. No file contents, Shell, automatic web access or targeted configuration reads are exposed. Purpose and rebuildability remain uncertain unless established through the investigation and user answers.

Budgets are 12 model steps, 32 tool executions, 8 suggestions and 3 questions; each turn has a 180-second timeout and 3072 output-token limit. Reported usage of 32000 tokens stops subsequent steps; a response may cross this threshold, so it is not a precise spending cap. Waiting does not consume a turn timeout; investigations cannot resume after 24 hours.

Provider response bodies are additionally limited to 1 MiB. The inspector exposes observed index evidence and each suggested directory’s measured size.

Jev is limited to 8 reviews, 24 KiB inputs and 64 KiB responses; reported usage counts toward the investigation token threshold. Neither service retries automatically or follows redirects. New macOS configurations never access Keychain. Legacy Keychain read/update/add operations prohibit interactive authorization and report an in-app repair message when unavailable. Switch to Local Key Storage asks for each key once, retaining old Keychain entries without reading or deleting them. Background saves prevent duplicates/dismissal; cancelling a test prevents subsequent Jev requests. Credential loading is excluded from the 180-second processing limit, with cancellation and enablement rechecked afterwards.

Private local checkpoints contain the chosen connection, scope, questions, SDK continuation messages and validated suggestions, without keys. Resume keeps the original provider. States distinguish waiting, complete, limited, cancelled and failed. Provider error bodies are not persisted or displayed, redirects are refused and requests are not automatically retried.

## Credential and scope interaction revision

Ordinary provider keys in [CC Switch](https://github.com/farion1231/cc-switch/blob/e4873bc8aa2555225d4867ec2f04b1290f1d21d9/src-tauri/src/database/dao/providers.rs) are persisted with local provider settings. Shou reuses atomic local storage instead of adding a database. The private `ai-credentials` directory is excluded from profiles, checkpoints, exports and derived-record collection. macOS enforces 0700 directories, 0600 regular single-link files, current ownership, no symlink following and an 8 KiB bound. Windows local mode reuses native ACLs and bounded atomic storage. Local files are permission-protected, not Keychain-encrypted, as disclosed in the editor.

Configuration choices display actual cooperating services, such as `Jev + gpt-6.1-sol`, and decision-first/on-demand roles. Launch scope offers the entire current scan or one physical directory, preferring the highlighted storage folder. Investigation never changes cleanup selection. Explicitly migrated local keys also support legacy checkpoint references without changing their saved endpoint or provider.

A user record stopped at 0 steps, 18 evidence rows and zero requests/tokens for both services after credential resolution exhausted the 180-second processing deadline. This did not indicate an exhausted account balance. Credential resolution is now excluded, and `limit_reason` identifies time, tokens, steps, decisions, tools, evidence, response or directories.

## Public contract

`shou capabilities --command ai --json` discovers fifteen operations, including `ai providers`, `ai list`, `ai cancel --investigation-id` and: `ai connections list [--state active|deleted|all]`, `ai connections show|delete|restore --connection-id`, `ai connections save --file`, `ai connections test --connection-id`, `ai connections credential save --connection-id [--service model|decision|jev]`, `ai connections decision test --connection-id`, `ai investigate --scan-id --connection-id [--path] [--request] [--goal investigate|space|rules]`, `ai show --investigation-id`, `ai resume --investigation-id --file`, and `ai advice import --investigation-id --advice-id`. Configuration deletion is recoverable and preserves historical credential references. Credential save reads standard input into the selected local or system credential store, accepting no key argument or profile-file secret. Decision tests send synthetic evidence. The `network` side effect explicitly identifies inference requests. Final JSON uses the existing envelope; failed/cancelled/limited investigations return partial with exit code 6 and retain available findings.

Profiles contain `id`, `name`, `api_protocol` (`responses`, `chat_completions`, `anthropic`), `base_url`, `model`, `authentication` (`keychain`, `environment`, `none`) and `environment_variable`. Profile/answer files are limited to 16 KiB, raw-key fields are rejected, and answers map current question IDs to strings. Import registers the scan root as a workspace if necessary and keeps the rule disabled. See the [Chinese examples](../zh-CN/engineering/embedded-ai-implementation.md).

An optional `decision` profile contains only `base_url`, `model`, `authentication` and `environment_variable`; its credential is stored separately. Bridge `ai.decision.test` verifies it.

Bridge v1 adds `ai.connections`, `ai.test`, `ai.investigate`, `ai.show`, `ai.resume` and `ai.advice.import`. Resume takes an `answers` object. Existing `kind: progress`/`value` and `kind: cancel` messages are reused; no cleanup confirmation bypass is added. SDK dependencies remain macOS-only. A bounded portable runtime supports the same three protocols on Windows and reuses the investigation, decision and rule service. Capability discovery reports the installed runtime. Legacy SDK checkpoints are not silently converted; incompatible runtimes require a new investigation.

## Configuration CRUD and decision switch

Every new saved/runnable profile requires a valid main model. `routing_strategy` controls Jev: `decision_first` enables assistance and `main_only` disables it and lets the main model take over, retaining `decision` and its separate credential. Disabled decision tests return `ai_decision_disabled` before reading credentials. Desktop connection tests verify enabled services only. Legacy Jev-only profiles remain readable for repair/removal but cannot start or continue.

macOS Settings exposes active configurations, service disclosure, per-row decision switch, default selection, create/edit/test, named deletion confirmation and restoration. Windows exposes matching management, editor and switch controls. Running/waiting tasks disable configuration mutations and retain their snapshots. Blank key input preserves the saved key. Disabling Jev requires no key re-entry.

The fifteen discoverable AI commands include `ai connections list [--state active|deleted|all]`, `show --connection-id`, `save --file`, `delete --connection-id` and `restore --connection-id`. Save with the same ID updates the profile. Show can read a deleted key-free profile. Removal writes `ai-connection-states` only, preserving snapshots and credentials; restore is required before editing/testing/starting. Bridge equivalents are `ai.connections`, `ai.connections.deleted`, `ai.connections.show`, `ai.connections.save`, `ai.connections.delete` and `ai.connections.restore`. These configuration operations send no network requests.
