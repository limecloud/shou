Нативная утилита очистки macOS с проверяемыми и многократно используемыми правилами для проектов разработки и приложений.

> **Статус: этап проектирования.** Приложение и CLI пока недоступны. Ниже описаны запланированные функции. Перевод README не означает, что приложение уже поддерживает этот язык.

## Зачем нужен Shou

Каталоги Rust `target`, зависимости Node.js, кеши проектов и результаты сборки могут регулярно заполнять диск Mac объёмом 500 ГБ. Назначение каталогов зависит от проекта: имени или размера недостаточно, чтобы решить, можно ли удалить данные.

Shou сохраняет проверенное решение об очистке как личное правило: **Найти → Разобраться → Создать правило → Просмотреть → Подтвердить → Использовать снова.** Изменения, которые можно выразить существующим форматом правил, не требуют обновления приложения. Новые возможности движка по-прежнему требуют обновления.

## Запланированные возможности

- **Анализ по проектам:** различать результаты сборки, установленные зависимости, исходный код и неклассифицированные данные в явно выбранных рабочих областях.
- **Личные правила:** задавать пути, признаки проекта, условия хранения и исключения, затем просматривать объекты и риски.
- **Независимые приложение и CLI:** общий движок для управления правилами, сканирования, планов и истории; каждый интерфейс работает самостоятельно.
- **Интерфейсы для существующих агентов:** Codex, Claude Code, WorkBuddy и подобные инструменты могут добавлять отключённые черновики правил через стабильную CLI и JSON. Shou не интегрирует модели, не разрабатывает и не размещает агентов.
- **Нативная архитектура:** Swift, SwiftUI и AppKit. Переносимое ядро в монорепозитории; будущая поддержка Windows потребует отдельной реализации и проверки.

## Проверка перед очисткой

Правила не расширяют права операционной системы. Черновики проходят проверку и предварительный просмотр; включение правила не разрешает удаление. Каждый запуск требует подтверждения конкретного плана. В CLI не предусмотрены параметры обхода подтверждения.

По умолчанию объекты перемещаются в Корзину. Безвозвратное удаление объектов этой операции требует отдельного подтверждения и не затрагивает остальные объекты Корзины. Объём перемещённых данных и фактическое свободное место показываются отдельно. `node_modules` — зависимости, требующие тщательной проверки, а не обычный кеш. Имена, файлы блокировки и возраст данных не гарантируют возможность повторного создания.
